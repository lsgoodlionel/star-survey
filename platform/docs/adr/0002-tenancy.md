# ADR 0002：租户隔离采用“每租户一套引擎实例”

- 状态：已用双实例越权穷举实测验证；部署规范中的强制项待落到交付脚本
- 日期：2026-09-20
- 关联：P0-00.5；总方案（多租户与隔离章节）
- 证据：[租户隔离越权穷举矩阵](../p0/tenancy-negative-matrix.md)

## 背景

LimeSurvey 引擎内部**没有租户概念**。`lime_surveys`、`lime_users`、`lime_permissions`、
`responses_<sid>` 全部以“一个安装 = 一个组织”为前提设计：`sid` 在一个安装内唯一，
RemoteControl 的 session key 只校验本库的 `lime_users`，答卷附件按 `upload/surveys/<sid>/files/` 落盘。
在引擎里加 `tenant_id` 字段意味着改动几乎每一张表和每一条查询，且每次跟上游合并都要重做。

因此隔离必须放在引擎之外：平台按 域名 → 问卷 UUID → 引擎实例 → sid 路由，
每个租户拿到独立的数据库、独立的数据库账号、独立的运行时进程与配置。

P0 的任务不是声明“我们加了 tenant_id”，而是**实测**：把两套实例摆在一起，
穷举一切越权路径，看每一次拒绝到底来自哪一层。

## 决定

1. **一个租户 = 一套引擎实例**：独立数据库、独立数据库账号、独立 Web 进程与配置文件、
   独立的 `tmp/` 与 `upload/` 卷。租户之间不共享任何可写路径。
2. **数据库账号只授本库权限**：`GRANT ALL ON tenant_x.*`，全局权限只有 `USAGE`。
   不给 `FILE`、不给 `mysql.*`、不给 `CREATE DATABASE`、不给 `GRANT OPTION`。
   即便两个租户被放进同一台数据库服务器，授权也必须是唯一的拦截点。
3. **代码树按租户独立**：每个租户用自己的镜像或自己的只读代码卷。
   以下文件**必须按租户独立**，不得共享：
   - `application/config/config.php`（数据库连接）
   - `application/config/security.php`（sodium 加密密钥）
   - `application/config/allowed_hosts.php`（可信域名白名单，引擎会自动生成）
   - `tmp/`（运行时缓存、资源发布、会话）
   - `upload/`（答卷附件、主题、插件）
4. **会话 cookie 按租户命名**：`session.name` 带租户前缀，不要都叫 `PHPSESSID`。
5. **网络按租户分段**：租户的 Web 只能连自己的数据库；DB 隔离不能只靠凭据。
6. **sid 不是跨租户标识**：平台对外只用问卷 UUID，`sid` 永远只在实例内部有意义。
   两个租户出现同号 `sid` 是正常状态，验证栈里就是故意这么造的。

## 验证

验证栈 `platform/deploy/tenancy/`（独立 compose 项目 `survey-tenancy`，宿主端口 8091 / 8092），
越权脚本 `platform/tests/e2e/tenancy_isolation.php`，一次完整跑批 17 个场景 / 61 次尝试。

验证栈**刻意放宽两点**，让结论更硬：两个租户在同一个 docker 网络里（网络层互通），
代码树是同一份绑定挂载。于是每一次拒绝都只可能来自授权、会话/权限、路由或独立卷。

| 面 | 尝试次数 | 结果 | 拒绝来自 |
|---|---|---|---|
| 直连数据库（跨服务器、同服务器共置库、枚举、提权、`LOAD_FILE`） | 14 | 全部被拒 | 数据库认证与授权（1044 / 1142 / 1045） |
| RemoteControl（对方凭据、对方 session key、伪造 key、未认证、本实例用对方 sid） | 11 | 全部被拒 | 引擎认证/会话；跨 sid 部分为实例路由 |
| 填写运行时（打开对方 sid、借用对方答卷 id、穷举 sid、同号问卷） | 10 | 全部被拒 | 实例路由（本库查不到该 sid） |
| 上传文件（跨实例取附件、目录穿越、匿名直取、目录列举、引擎日志） | 7 | 全部被拒 | 每租户独立卷；同实例内靠 `.htaccess` |
| 后台路由（偷会话打邻居、合法会话用对方 sid、浏览/导出/下载、未认证） | 11 | 全部被拒 | 引擎会话；跨 sid 为路由＋应用层权限检查 |
| 共享缓存/临时目录/代码树 | 8 | **4 项未被拒绝** | 见下 |

几条值得单独记的观察：

- **同号 sid 不会串**：`555001` 在两个实例上都存在，A 用自己的 key 导出 `555001`
  拿到的始终是 A 的答卷（`TENANT-A-DECOY-ANSWER`），从未出现 B 的金丝雀。
- **共置数据库也拦得住**：在 `db-a` 上额外建了一个叫 `tenant_b` 的库，
  `tenant_a` 账号连 `SHOW DATABASES` 都看不到它，`information_schema` 按权限过滤后返回 0 行。
- **跨实例偷会话无效**：把 A 的 `PHPSESSID` 直接塞进打向 B 的请求头，B 返回登录表单。
  会话存储在各自容器里，互不可见。
- **阳性对照都成立**：B 上确实能读到金丝雀、A 上导出路由对自己的 sid 确实返回 200。
  排除了“因为什么都没跑起来所以全都拒绝”这种假阴性。

### 未被拒绝的四项（全部源于共享代码树）

| 编号 | 发现 | 影响 |
|---|---|---|
| F-01 | A 在共享目录写下一个 `.php`，**B 的实例用自己的身份执行了它**，探针用 B 的 `config.php` 连上 B 的库并取回了 B 的问卷标题 | 等价于跨租户 RCE，隔离完全失效 |
| F-02 | 共享代码树里任意非隐藏文件都能从邻居实例通过 HTTP 读到 | 配置与业务代码互相可见 |
| F-03 | `application/config/security.php` 共享，两个实例 sodium 加密密钥相同 | 一个租户的密文可被另一个租户解密 |
| F-04 | `application/config/allowed_hosts.php` 由管理员首次登录自动生成，也落在共享目录。实测中 A 的管理员一登录，B 的全部请求变成 `400 Bad Request` | 跨租户可用性事故 |

这四项**不是引擎缺陷，是部署形态缺陷**：它们全部且仅在“多个租户共用代码树/配置目录”时成立，
也正是决定 3 把那五类路径列为强制独立的原因。验证栈随后按租户挂载 `allowed_hosts.tenant-*.php`，
F-04 即消失。

### 资源开销

空载状态，每租户一套（Web + MariaDB）：内存约 300 MiB，磁盘约 220 MB（DB 149 MB + tmp 71 MB），
引擎表 60 张，引擎镜像 729 MB 多租户共用。

## 已知限制与后续

- [ ] **把决定 3 的五类路径写进交付部署脚本并加开机自检**：实例启动时校验
      `security.php`、`allowed_hosts.php`、`tmp/`、`upload/`、`config.php` 是否为本租户独占，
      不满足就拒绝启动。目前只有本验证栈按租户挂载，交付侧尚无强制。
- [ ] 会话 cookie 仍是默认的 `PHPSESSID`。同域名不同端口部署时浏览器会互相覆盖会话，
      需要按租户设置 `session.name`（决定 4 尚未落地）。
- [ ] 网络层未分段：验证栈里拿到对方数据库口令即可直连（决定 5 尚未落地）。
      交付时需要按租户划分网络或加数据库侧的 host 限制。
- [ ] `upload/surveys/*/files/fu_*` 与 `tmp/runtime/` 的匿名访问防护完全来自引擎自带的 `.htaccess`
      （本镜像 `AllowOverride All` 才生效）。若改用 nginx 或关掉 `AllowOverride`，
      知道 sid 与文件名即可匿名下载答卷附件，需要在 Web 服务器配置里显式重建这两条规则。
- [ ] 后台“本实例没有这个 sid”的拒绝落在应用层 `hasSurveyPermission()` 上，不是数据库授权。
      这条属于纵深防御的最外层，不应作为唯一依赖。
- [ ] 未覆盖：参与者/令牌表（`lime_tokens`）的跨实例尝试、插件安装面、
      定时任务与邮件发送的跨租户影响、PostgreSQL 下的同等矩阵。
- [ ] 规模化成本未评估：每租户约 300 MiB 内存是空载值，需要在 P0-00.8 里结合并发与答卷增长核算。
