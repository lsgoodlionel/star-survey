# ADR 0011：资源树管理与发布审批的产品规则

- 状态：已接受（2026-09-22，用户逐项确认）
- 关联需求：R01-09 发布审核、R19-01 子账户与项目分配、R19-04 文件夹及协作员

## 决定

1. **建项目**：只有在租户级拥有 `manage-settings` 的成员（所有者、管理员）能创建项目；创建者自动获得该项目的管理授权。
   对项目或文件夹有 `edit` 的成员可在其下创建文件夹与问卷。
2. **移动**（R19-04，默认规则）：移动文件夹或问卷需要对源位置和目标位置都有 `edit`；移动后按新位置重算继承的授权，
   直接挂在被移动节点上的授权保留。不得把节点移到自己的子孙下，也不得跨项目移动到无权的项目。
3. **审批人**：在该问卷或其上级文件夹 / 项目上拥有 `approve-publish` 的成员可以批准；**允许申请人批准自己的申请**
   （前提是其本人拥有 `approve-publish`）。审批动作一律写审计。
4. **批准绑定草稿版本**（R01-09）：申请记录提交时的 `draft_version`；此后草稿只要再保存，该批准即作废，须重新提交。
   通过 API 发布同样受此约束，不能绕过。
5. **发布触发**：批准后由申请人（或任何对该问卷有 `publish` 的成员）自行点发布，发布的必须正是被批准的草稿版本；
   发布失败可重试，批准在草稿未改动前一直有效。

## 取舍

- 允许自批使单人团队不必另设审批人，代价是审批对拥有 `approve-publish` 的人不构成职责分离；需要分离的租户通过
  不把 `approve-publish` 与 `publish` 授给同一人来实现。
- 改稿即作废比锁定草稿更灵活，且不存在"小改"的边界争议。
