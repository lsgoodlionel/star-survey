# ADR 0010：业务平台技术栈与多租户隔离机制

- 状态：已决定
- 日期：2026-09-21
- 关联：P1；总方案 §3.1、§3.3；WP-23

## 决定

| 项 | 选择 | 说明 |
|---|---|---|
| 语言与框架 | Java 21 + **Spring Boot 4.1.1** | 总方案写"3.x 受支持版本"。3.5 的开源支持已于 2026-06 结束，新项目上 3.x 等于一开始就用过保版本；按方案本意（受支持版本）选 4.x 当前线 |
| 数据访问 | `JdbcClient` + Flyway | 显式 SQL，便于审查租户隔离；不引入 ORM 的隐式行为 |
| 数据库 | PostgreSQL 16 | 与 P0 结论一致 |
| 构建 | Maven 在容器内运行，依赖走镜像源 | 本机不装 Java；私有化交付替换为客户内网镜像 |
| 身份 | 无状态 JWT，P1 用 HMAC 共享密钥验签 | 接入 Keycloak 后改为按发行方 JWK 验签，其余代码不变 |

## 多租户隔离：由数据库强制，不靠业务代码自觉

1. 两个数据库账号：`platform_owner` 执行迁移并拥有表；`platform_app` 供应用运行，**不拥有表、没有 BYPASSRLS**。
2. 每张租户表 `ENABLE` 且 `FORCE ROW LEVEL SECURITY`，策略为 `tenant_id = app_current_tenant()`。
3. `TenantScope` 在事务内执行 `set_config('app.tenant_id', …, true)`：事务结束即失效，不会随连接池串到下一个请求。
4. 未设置租户时 `app_current_tenant()` 为 NULL，任何比较都不成立——**没有租户上下文等于什么都看不到、什么都写不进**。
5. 租户只从已验签令牌的 `tenant_id` 声明取；请求头、查询参数不参与。

## 验证

`platform/services/business` 骨架 15 个测试全部通过：B 读不到 A 的审计记录；在 B 的上下文里写 A 的行被数据库以"违反行级安全策略"拒绝；无上下文时读为空、写被拒；运行期账号经核验不能绕过；租户设置不泄漏出作用域；无令牌 401、令牌缺租户声明 403、篡改令牌 401、`X-Tenant-Id` 头无法覆盖令牌里的租户。

## 已知限制

- HMAC 共享密钥只适合开发与单体部署；多服务或对外发令牌前必须切换到非对称签名。
- 行级安全挡住的是跨租户越权；同一租户内的角色与资源权限由 `access` 模块负责。
