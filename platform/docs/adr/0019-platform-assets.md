# ADR 0019：平台资产服务（WP-02 前置能力）

- 状态：切片 02.6 已实现（2026-09-24），待集成审查
- 关联需求：R02-20 轮播图（媒体版本留存）、R02-21 视频题（授权播放）、R02-25 答题录音、R02-26 答题摄像、
  R02-32 双码拼接、R02-39 绘制签名、R02-41 考试绘图——七类插件题型全部卡在本服务上
  （见 `platform/docs/p2/question-type-map.md` 第六节）
- 关联 ADR：0002（租户隔离）、0006（题型承载与上传会话）、0008（私有化交付的出网约束）、
  0015（导出作业的文件存储与再次授权）、0016（作答者身份）、0018（匿名可达面的统一拒绝）
- 契约：`platform/contracts/survey-assets-v1.md`

## 背景

题型车道走到第五批时停在同一堵墙前：**平台没有自己的资产**。

- 图片地址（图片 PK 的参赛图、货架图、热力图底图、心理实验的刺激）一直是**作者填的一串 URL**，
  发布时只校验「非空字符串且不超长」——`javascript:`、`data:`、内网地址、第三方站点全都能过
  （`pubgw/questions/theme_kit.py` 的 `text` 分支没有为任何一个图片选项设 `pattern`）。
  作者换掉那张图，已经发出去的问卷跟着变，答卷与当时看到的图对不上。
- 引擎自己的上传题（type `|`）落在**每租户独立的 `upload/` 卷**里（ADR 0002 决定 3），
  平台够不着，也没有平台侧的资产 id；ADR 0006 决定 4 早就为此在上传会话表里留了
  `upload_token = 平台侧资产 id` 这一列，但平台侧一直没有对应的东西。

七类题型要的能力可以归成三件事：**留存**（同一张图的第几版，发出去之后不许变）、
**授权取件**（作答者拿得到，无关的人拿不到）、**作答者上传**（录音、录像、画布快照）。
本 ADR 落地前两件，并为第三件定下不得倒退的约束。

## 决定

### 1. 资产是「版本化的二进制 + 平台侧元数据」，元数据在 PostgreSQL，字节在对象存储

三张表（迁移 V900，模块号段 V900–V999）：

| 表 | 内容 | 可变性 |
|---|---|---|
| `platform_asset` | 一件资产：租户、id、类别（image/audio/video）、名称、状态（active/archived）、当前版本号 | 名称与状态可改 |
| `platform_asset_version` | 一个版本：存储键、内容类型、字节数、SHA-256、原始文件名 | **内容不可改**（`REVOKE UPDATE`） |
| `platform_asset_reference` | 哪一版问卷引用了哪一件资产的哪一版 | **只追加**（`REVOKE UPDATE, DELETE`） |

版本行保留 `DELETE` 权限：无人引用的整件资产可以连同字节一起删掉（决定 6）。不保留 `UPDATE`——
改一行就等于"已发布的问卷里那张图被换掉了"，而版本留存正是本服务存在的理由。

三张表都是租户表，按 CONVENTIONS.md 的四行启用 `ENABLE + FORCE` 行级安全，跨表外键一律带 `tenant_id`
（外键检查绕过行级安全，这是第二波组织免登安全审查的结论）。

**字节永远不进 PostgreSQL**，与 ADR 0015 的导出文件同一口径：库里只存
`storage_key + byte_size + sha256`。

### 2. 存储只有一份抽象：`BlobStore`（回答"导出多实例需共享存储"这条遗留）

ADR 0015 为导出文件定义了 `ExportFileStore`（`create/open/exists/size/delete/deletePrefix`，
键为小写 `[a-z0-9.-]` 分段，写入先落临时文件再原子改名）。资产面对的是**同一个问题**，
因此不另起一套：把那个接口原样提升为 `cn.mjy.platform.shared.storage.BlobStore`，
本地实现 `LocalBlobStore` 也只留一份；`ExportFileStore` 降为
`interface ExportFileStore extends BlobStore {}`（一行，不加任何成员），导出模块的代码一字未改。

于是**"生产换成对象存储"这件事只需要做一次**：写一个 `BlobStore` 实现并注册成 bean，
导出文件与资产同时切过去。多副本部署时两者共享同一份存储，不会出现"导出用共享卷、资产用另一套"。

资产的键形如 `asset/<租户 uuid>/<资产 uuid>/v<版本号>`，全部由平台生成，**没有一段来自调用方文本**；
原始文件名只作为元数据存进库里，从不参与路径。目录穿越在 `BlobStore.requireKey` 与
`LocalBlobStore.resolve` 两处各挡一次。

**二进制的租户隔离**靠三条叠起来：键里带租户 uuid；键**只能从行级安全作用域内读出来的元数据行**取得，
从不由请求参数拼；本地实现再校验解析后的路径没有逃出根目录。换句话说，拿不到那一行元数据就拼不出键——
隔离的判定点仍然是行级安全，存储层只是不给第二条路。

**静态加密**沿用 ADR 0015 的结论：应用层不做，要求部署层提供（磁盘加密或对象存储服务端加密）。

### 3. 上传是系统边界：类型、大小、内容三道闸门

`POST /v1/assets`（multipart）与 `POST /v1/assets/{id}/versions`（新版本）：

1. **大小**：`platform.asset.max-bytes`（默认 16 MiB）由 Spring 的 multipart 上限与服务端再判一次；
2. **类型**：只接受白名单里的内容类型（image/png、image/jpeg、image/gif、image/webp、
   audio/mpeg、audio/wav、audio/webm、video/mp4、video/webm），**并按类别归组**；
3. **内容**：读出文件头按魔数（magic bytes）认一遍，与声明的内容类型**必须一致**，不一致即 400。
   存进库里、之后回放时使用的是**嗅探出来的**内容类型，不是调用方声明的。
   WebP 与 WAV 共用 RIFF 容器，**必须认到第 9–12 字节的格式标识**：只判「是不是 RIFF」的话，
   一段音频可以声明成 `image/webp` 存下来，之后就以图片的内容类型被回放（独立审查抓到的一条）。

**SVG 一律拒收**。它是可执行文档（内嵌 `<script>`、外部实体），一旦以 `image/svg+xml` 在平台域名下回放，
等于在平台域上给了任意脚本执行点。需要矢量图就先转成 PNG/WebP。同理不接受 `text/*` 与 `application/*`。

回放响应固定带 `X-Content-Type-Options: nosniff`、`Content-Disposition: inline` 且文件名只由平台生成、
`Content-Security-Policy: default-src 'none'; sandbox`——纵深防御：即便将来白名单被放宽错了，
浏览器也不会把它当文档执行。

### 4. 匿名作答者怎么取资产：**签名取件票**，密钥按租户派生，票据随定义快照固化

这是本 ADR 最难的一点。约束有三条，彼此矛盾：不能是公开可猜的 URL；作答者往往没有账号，
不能要求登录；**引擎的作答页调不到 Java 平台**——平台只和网关说话，网关只和引擎说话，
引擎到平台只有 cron 驱动的事件回传（ADR 0018 决定 9 与 ADR 0008 的出网约束）。

因此唯一可行的形状是：**把票据交给浏览器**，与短链 `/d/s/{code}` 同一条路——
作答者的浏览器本来就能访问平台的对外地址 `PLATFORM_PUBLIC_BASE_URL`。

```
<公开地址>/a/<租户 uuid>/<资产 uuid>/<版本号>?exp=<秒>&sig=<base64url>
签名对象（沿用 SignedParameters 的规范串）：
    "asset/v1/<租户 uuid>/<资产 uuid>/<版本号>" \n <过期秒> \n ""
密钥：HMAC-SHA256(PLATFORM_ASSET_SECRET, "mjy-asset/v1/fetch/" + 租户 uuid)
```

- **签名实现只有一份**：`SignedParameters`（WP-05 投放链接用的那一套，已有跨实现向量测试）
  从 `cn.mjy.platform.delivery` 提升到 `cn.mjy.platform.shared.security`，资产与投放共用。
  规范串里键值各自百分号编码，`exp` 与 `sig` 是保留名——参数拼不出第二组含义。
- **上下文覆盖租户、资产、版本三者**：改任何一个都验不过，因此不能把 A 租户的票改去取 B 租户的资产，
  也不能把第 1 版的票改去取第 2 版。资产 id 是 UUID，签名是 256 位 HMAC，**猜不出来**。
- **密钥按租户派生**：一个租户的密钥泄露推不出别的租户的（沿用 `DeliveryKeys`/`EngineEventKeys` 的形状）。
  主密钥缺失时应用照常启动，但签发与验签一律 503——失败即关闭。
- **票据在发布时签发，随定义快照固化**：`exp = 发布时刻 + platform.asset.ticket-ttl`（默认 180 天）。
  发布快照是不可变的，核对重发时逐字节相同，因此票据不会因为重试而变化。改版再发布重新签发。

**这仍然是 bearer 语义**：拿到链接的人能看到那张图。这是**故意的**，也与作答链接本身同构——
问卷媒体是发给每一个作答者看的，作答链接自己就是 bearer。本决定要挡住的是"不知道链接也能拿"
（枚举、改签名、换租户、换版本、过期后继续用），不是"拿到链接的人转发给别人"。
真正的私密资产（答卷附件、考试答案快照）**不走这条路**，见"已知限制"第 2 条。

**拒绝口径**（ADR 0018 决定 5 的匿名可达面规则）：验签及其之前的一切失败——路径形状不对、缺 `exp`/`sig`、
`exp` 不是数字、签名不匹配、主密钥未配置、资产或版本不存在、资产已停用——返回**逐字节相同**的
`404 {"error":"not_found"}`，`Cache-Control: no-store`，原因只进服务端日志。
唯一的例外是**签名正确但已过期**：返回 410，因为走到这一步的人本来就持有过合法链接，
告诉他"过期了"不泄漏任何他原本不知道的事，却能让前端给出有用的提示。

**验签之前零数据库 IO**：路径解析与 HMAC 都是纯进程内计算，验签通过之后才带着
**票据里那个（已签名的）租户 uuid** 进 `TenantScope` 读元数据。因此不需要
`delivery_short_link` 那种"先认出租户"的控制平面表——租户是签名的一部分。
（ADR 0018 那条被独立审查抓到的 `ensureSchema()` 教训：这个不变式很容易在接线时被顺手破坏，
本切片为它单独留了一条测试。）

成功的应答带 `Cache-Control: private, max-age=3600`：`(资产, 版本)` 的字节是不可变的，
让浏览器缓存是对的；`private` 挡住共享缓存与 CDN。这与拒绝路径的 `no-store` 不冲突。

### 5. 定义里写资产 id，发布时才换成签名地址——版本就是在这一刻钉死的

草稿定义里题型主题写的是 `themeOptions.slides[].assetId`（加 `alt` 替代文本）；
发布时平台在 `SurveyDefinitions` 之后、发给网关之前，把每个 `assetId` 解析成
`{url, assetVersion}` 并**删掉 assetId**，同时往 `platform_asset_reference` 登记一行。

- 解析取的是**发布那一刻的当前版本**，写进快照。作者之后上传新版本，已发布的那一版**纹丝不动**——
  这就是需求里的"媒体版本留存"。想让在线问卷用新版，必须改版再发布（ADR 0012），
  与问卷的其他改动同一条路、同一份审批。
- 接缝是 `SurveyAssetSource`（`cn.mjy.platform.survey` 里的接口，实现在 `cn.mjy.platform.asset`），
  形状照抄 `SurveyParticipantSource`：问卷模块不认识资产，资产模块不参与发布。
  没有注册实现时，**带资产引用的问卷发不出去**（而不是发出一份图全裂的问卷）。
- 网关只看见 `url`，不认识 `assetId`。**平台管资产，网关管题型形状**，两边不互相复制规则。
- **作者自带地址怎么挡住。** 网关分不出「平台签发的地址」与「作者自己填的地址」——它没有验签的密钥。
  光在平台侧写「带 `url` 的引用不许同时带 `assetId`」也不够：作者可以干脆不写 `assetId`，
  改写器根本不会访问那个对象。所以规则由两侧合起来定，缺一不可：
  **平台侧**草稿里任何一处出现 `assetVersion` 即判定义非法（它只由平台在解析 `assetId` 时写入），
  **网关侧**每一种带资产的主题都必须把 `assetVersion` 列为必填。
  于是作者自带的地址凑不齐一条合法的引用。新增媒体类主题时这两条要一起满足。

### 6. 生命周期：引用即不可删，只能停用

- 被任何一版问卷引用过的资产**不能删除**（`409 asset_in_use`），只能 `archive` 停用：
  停用后不能再被新的发布引用，已发布的问卷照常回放——已经发出去的问卷不该因为后台点了一下就图全裂。
- 没有任何引用的资产可以删除：元数据行删掉、全部版本的字节按前缀删掉。
- 不做引用计数整数（计数会漂移、会对不上），只按引用行 `EXISTS` 判定。

### 7. 与上传会话的关系：只加强，不倒退

现有约束"伪造上传文件列表须以上传会话为准"（ADR 0006 限制 3，
`question-type-map.md` 第五节记为未覆盖项）**保持不变，并由本 ADR 接管为硬约束**：

- 本切片的资产端点**全部要求已认证的作者身份**（主安全链的 JWT ＋ `access` 模块判定），
  `/a/**` 匿名链上**只有 GET 一个只读端点**，拿着取件票**创建不了、改不了、删不了**任何东西。
  这一条有专门的篡改用例钉住。
- 将来接 R02-25/26/39/41 的作答者上传时，资产行由**上传会话**驱动创建
  （`upload_token` 即资产 id，ADR 0006 决定 4 早已预留），
  **绝不接受作答者直接调用平台的上传端点、也绝不信任答卷里那张文件清单**。
  平台侧的资产行是唯一事实来源，引擎答卷里的清单只是线索。
- 附件打包（ADR 0015 遗留，仍卡在 `get_uploaded_files` 的整卷 base64）将来的出路也在这里：
  附件一旦以资产形式落在 `BlobStore` 上，打包就是按引用逐件流式读，不再受那个端点的内存约束。
  本切片不做，但存储抽象与键结构是照这个方向留的。

## 独立安全审查（2026-09-24，实现之后另跑一轮）

按「读改动面、质疑每一条不变式」的口径过了一遍。**三条属实并已修**，其余为记录在案的接受项。
其中那条 CRITICAL 不是单元测试能发现的类别：本车道原有的用例只证明了
「`url` 与 `assetId` 同时出现会被拒」，而漏洞正是它的反面——**只看绿灯会整条漏掉**。

| 级别 | 发现 | 处理 |
|---|---|---|
| **CRITICAL** | **作者不写 `assetId`、直接填 `url` ＋ `assetVersion`，就能把任意地址发到作答页上。** 改写器只访问带 `assetId` 的对象，这种对象它从来没看过；网关又分不出地址是谁签的。于是版本留存、上传闸门、同源取件全被绕开，作答者的浏览器被指使去访问第三方（泄漏 IP／UA／Referer）。**定性**：作者本来就能用热力图底图那几处填 URL，所以不是新增的越权能力；真正坏掉的是决定 5 里「作者不能自带地址」这句**不变式为假**——而资产服务存在的理由正是这句话。 | 规则反过来定：`assetVersion` 是平台写的键，草稿里出现即判定义非法；网关侧每种带资产的主题都必须把它列为必填。两条合起来，作者自带的地址凑不齐一条合法引用。先写两条用例见红（`anAuthorSuppliedAddressWithoutAnAssetIdIsRefused`、`anAuthorSuppliedAssetVersionIsRefused`）再改。 |
| MEDIUM | **缺主密钥时发布失败会变成 500 而不是 503**。资产模块的错误映射挂在 `cn.mjy.platform.asset` 上，而发布是从问卷模块的控制器进来的，接缝抛出的 `AssetUnavailableException` 落到没人接的地方。「失败即关闭」是成立的（问卷确实没发出去），但状态码骗人。 | 接缝改抛问卷模块的 `PublishUnavailableException`（与「网关没配」同一类）。先写用例见红（`SurveyAssetUnavailableTest`）再改。 |
| LOW | **RIFF 容器只判了前四字节**，WAV 可以声明成 `image/webp` 存下并以图片类型回放。`nosniff` ＋ CSP 让它够不着脚本执行，但「存下来的类型是嗅探出来的」这句不变式此前为假。 | 按类型逐个认第 9–12 字节。先写用例见红（两条）再改。 |
| 接受 | **`/a/**` 没有限流**。伪造签名的洪水只花一次进程内 HMAC、不碰数据库（这正是「验签前零 IO」的用处）；但持有一张合法票的人可以高频重放，每次一读库一读盘。与 `/d/**` 的现状同一口径。 | 记为遗留（第 8 条），要做就该和 `AnonymousRateLimitFilter` 一起做，不在本切片各造一套。 |
| 接受 | **`content_type` 在 SQL 里只限长度，没有限定白名单**。白名单的唯一真相在 Java 的 `AssetContentTypes`；在迁移里再抄一份会漂移。 | 不加。写入路径只有一条，且已有用例钉住「存下来的类型是嗅探出来的」。 |
| 接受 | **魔数只看文件头**，挡的是「声明成图片的可执行文件」，不是「真的是图片但带恶意载荷」。 | 病毒扫描是独立的一件事（已知限制 3）。 |
| 接受 | **取件票是 bearer**：拿到链接的人能看到那张图。 | 这是决定 4 写明的取舍——问卷媒体本来就是发给每个作答者看的，作答链接自己也是 bearer。真正私密的资产不走这条路（已知限制 2）。 |
| 核实成立 | 删除与发布的竞态：发布侧读资产行**不加锁**。若删除先提交，发布侧插引用行会撞外键、整笔回滚（发布失败）；若发布先提交，删除侧的级联会被引用行的外键挡住。两个方向都不会留下「问卷指着已删掉的字节」。 | 不改。加 `FOR UPDATE` 会把两次发布之间也串起来，凭空造出死锁面（资源树移动那次的教训）。 |
| 核实成立 | 递归改写定义的深度：定义在 `SurveyDefinitions.normalize` 里已被 1 MiB 上限卡住，且 Jackson 自带嵌套深度上限，`SurveyAssetSource.references` 的递归因此有界。 | 不改。 |

## 验证

- Java 单测：上传闸门（大小/类型/魔数/SVG/空文件）、版本留存、引用与删除守卫、跨租户负面测试
  （直接写裸 SQL 指名别的租户，由数据库拒绝）、取件票的四类篡改（改签名、改租户、改资产、改版本）、
  过期票、未配置主密钥、匿名票据不能写。
- 发布链路：带资产的定义在发布时被改写成签名地址并登记引用；资产不存在／跨租户／已停用时发布失败。
- 真引擎双库端到端：`run-question-themes.sh`（MariaDB 10.11 与 PostgreSQL 16 各一遍）里
  R02-20 轮播图的渲染、作答、篡改场景。

## 已知限制与后续

1. **票据有效期是固定 TTL（默认 180 天），到期只能靠改版再发布刷新。**
   真正的做法是让作答页在票据将过期时换一张新的，但那需要引擎→平台的在线通道，
   与 ADR 0008 的出网约束冲突，本切片不做。长期投放的问卷需要运维注意这一条。
2. **本切片的授权是"发给所有作答者看"这一档**，不是"只有这一位作答者能看"。
   答卷附件、考试答案快照（R02-41、WP-09）需要按作答者身份授权，
   而作答者身份只有引擎/插件知道（ADR 0016），平台要么经网关问一次，要么把票据绑到参与者令牌上——
   两条路都要先扩 ADR 0018 的通道，不在本切片。
3. **没有病毒扫描**。魔数校验挡住的是"声明成图片的可执行文件"，不是"真的是图片但带恶意载荷"。
   接 ClamAV 之类需要新依赖与部署面，留给运维切片。
4. **没有图片处理**：不生成缩略图、不重编码、不剥离 EXIF。作者上传的照片里的 GPS 与设备信息
   会原样发给作答者。R02-32 的"图片合成"因此仍未解锁。
5. **`BlobStore` 目前只有本地实现**，多副本部署仍需共享卷。对象存储实现是独立的一件事，
   做完即导出与资产一起受益。
6. **按前缀删除不是原子的**：删到一半崩溃会留下孤儿字节，没有后台清扫。
7. 资产没有资源树授权（不是资源节点），按租户级权限判定：读需 `view`，写需 `edit`。
   "某个项目的素材只给某些人用"要等资源树支持挂资产。
8. **匿名取件端点 `/a/**` 没有限流**（见上表的接受项）。要做应当与
   `AnonymousRateLimitFilter` 一起做，别各造一套。
