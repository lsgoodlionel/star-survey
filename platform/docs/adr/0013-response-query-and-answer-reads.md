# ADR 0013：答卷查询的数据来源与字段字典（WP-06 切片 06.1）

- 状态：已实现（2026-09-22），待集成审查
- 关联需求：R06-01 原始答卷筛选查询（本切片覆盖：按问卷 / 状态筛选、游标分页无重复无遗漏、字段权限生效）；
  R06-09 中"统计权限不能下载明细"的服务端判定（分享本身不在本切片）；为 R06-02/R06-03 提供字段字典与版本映射
- 关联：ADR 0003（答卷事件与投影）、ADR 0005/0009（发布与绑定）、契约 `platform/contracts/response-read-v1.md`

## 背景：投影里有什么

`response_projection`（V301）只有**状态与时间戳**：自然键 `(实例, sid, 代次, 答卷号)`、`state`、`first_event_at`、
`completed_at`、`deleted_at`、`last_event_id`。引擎事件（`MjyPlatformBridge` → `/internal/engine-events`，
信封 `schemaVersion=1`）同样只带键与类型，**不带任何作答值**。作答值只存在于引擎的 `responses_<sid>` 表。

## 可选方案

| 方案 | 做法 | 否决 / 采纳理由 |
|---|---|---|
| A. 事件携带作答 | 扩展桥接插件的事件信封，把整行作答随 `response.saved` 发给平台 | **否决**。`saved` 每页保存都会触发，30 万答卷 × 多页 = 海量重复 PII 流经中继与收件箱（只追加、不可删）；隐私上等于在平台复制一份不受字段权限约束的明细；信封体积随题量线性增长，1 MiB 批次上限很快撞到；中途改题需要同步升级信封版本。 |
| B. 平台直连引擎库 / RemoteControl | 平台持有引擎数据库账号或管理员口令 | **否决**。违反"引擎管理员口令只在网关"（契约 publish-gateway-v1），私有化部署下还要开放客户机房数据库。 |
| C. **按需经网关读取（采纳）** | 平台只分页自己的投影；对当前页的答卷号，经网关新端点 `POST /v1/responses/read` 取作答值，网关用 RemoteControl `export_responses`（JSON、题目代码表头、短答案、按答卷号区间）读引擎 | 口令留在网关；平台只按**自己租户的已发布版本**里记录的 `(实例, sid)` 发起读取（行级安全保证拿不到别的租户的 sid）；每次只读一页，内存与报文有界；分页键在平台侧，天然支持 06.2 的分批导出。 |

## 决定

1. **分页在平台，作答按页补取。** 列表 = 投影行（状态、时间、版本标签）＋该页答卷的作答值。游标是
   `(版本号, 代次, 答卷号)`，每个版本内按投影主键 `(代次, 答卷号)` 键集翻页（走主键索引）。键是不可变的自然键，
   因此**翻页期间有新答卷写入也不会重复、不会漏掉翻页开始时已存在的行**；新行按键序或在本轮出现、或不出现。
   状态筛选下，翻页途中改变状态的答卷可能出现或消失——这是"按当前状态筛选"固有的语义，06.2 导出另建快照水位线。
2. **版本标签**：问卷的每个已发布版本绑定一个 `(实例, sid)`；投影行按 `(实例, sid)` 归入版本，不同 sid 的答卷不会混在一起。
   若多个版本指向同一 `(实例, sid)`（当前发布流程不会产生），归入其中版本号最大者。
3. **代次**：`export_responses` 只能读当前答卷表。同一 sid 出现多个代次时，只为**最近出现的代次**（按该代次最晚的
   `first_event_at`）补取作答，其余代次的行返回 `answersStatus = archived`，绝不把新代次同号答卷的作答挂到旧行上。
   残余风险见下。
4. **字段字典** `GET /v1/surveys/{id}/fields`：每个已发布版本一段，逐列给出题目 UUID、题目代码、题型、引擎列名、
   aid、尺度、题干 / 子题标签、选项标签、是否敏感。数据全部来自发布时冻结的定义快照与绑定映射，不访问引擎。
5. **敏感字段**：题目定义上的布尔属性 `"sensitive": true`（平台元数据，网关忽略未知键，不进引擎）。该题的所有列都敏感。
6. **数据权限**（服务端判定，全部经 access 模块）：
   - 问卷不存在或属于别的租户 → 404；
   - 列表明细 `GET /v1/surveys/{id}/responses`（同 `GET /v1/responses?surveyId=`）需要 `view-raw-responses`；
     只有 `view-statistics` 的统计查看者 → 403，**拿不到任何逐行数据**（含时间戳）；
   - 有明细权限但没有 `view-sensitive-fields` → 敏感列的非空值替换为 `ResponseFieldPolicy.MASK`（`ResponseFieldPolicies.forResponses`）；
   - 统计查看者可用 `GET /v1/surveys/{id}/responses/summary`（按版本、状态计数，需要 `view-statistics`）；
   - 字段字典只要 `view`（不含作答）。
   - 每次明细查询写审计 `response.list`（资源 `survey/<id>/responses`）。
7. **网关读端点**是新模块（`pubgw/responses.py`），只在 `server.py` 里登记路由；认证复用发布的 HMAC 密钥与签名规则；
   网关不做业务授权。单次最多 500 个答卷号、5000 个列名；答卷号按间距 ≤ 200 分段调用 `export_responses`，
   避免稀疏答卷号把一次读取放大成全表导出。
8. 网关不可达或引擎报错时，明细查询 503 `answers_unavailable`，不返回"看起来完整、其实缺作答"的页。

## 残余风险与后续

- [ ] **代次切换窗口**：问卷被停用再激活、而新代次的第一个事件尚未到达平台时，旧代次仍被当作"最近代次"，
  其答卷号可能与新表里的同号答卷相撞。平台发布的问卷不会被平台停用再激活，只有引擎后台人工操作会触发。
  后续：网关从桥接插件的代次表读当前代次并随作答返回，平台逐行比对。
- [ ] **06.2 导出**：30 万答卷分批导出需要快照水位线（翻页开始时记录各版本的最大键）与可恢复作业；本切片的键集游标已满足"无漏重"的前提。
- [ ] 状态筛选下每页是"主键扫描＋状态过滤"，某状态极稀疏时单页扫描量大；需要时在 engine 模块补 `(…, state, generation, response_id)` 索引。
- [x] `export_responses` 以 JSON 输出时表头是题目代码，网关按请求列的顺序做位置对应（首列固定为 `id`，并校验列数）。
  源码依据：`Writer::write` 按 `selectedColumns` 顺序输出；真引擎验证：`run-response-read.sh` 在 MariaDB 10.11 与
  PostgreSQL 16 上逐列核对（单选＋其他、多选带评论、双尺度、短文本、说明文字共 12 列）通过。
- [ ] 本切片没有新表，因此没有占用 V600–V609；06.2 的导出作业表从这里开始编号。
