# ADR 0008：私有化与离线交付形态

- 状态：气隙安装、备份恢复、成本基准均已实测；信创目标组合只做了可行性分析，未实测
- 日期：2026-09-20
- 关联：P0-00.8；ADR 0001（引擎基线）、ADR 0002（租户隔离）、[sbom/licence-analysis.md](../p0/sbom/licence-analysis.md)
- 证据：[私有化交付](../p0/private-deployment.md)、[成本模型](../p0/cost-model.md)
- 交付脚手架：`platform/deploy/private/`

## 背景

P0 进度表里 00.8 原本只记了一句「GitHub clone、Docker Hub、Packagist 均出现超时，
需要内网镜像源方案」。那是**开发侧**的网络问题，不是交付侧的结论。
真正要回答的是三个问题：

1. 一台没有外网的机器上，装这套东西到底还缺什么？
2. 引擎自己会往外打哪些请求？关得掉吗？
3. 一个租户到底多少钱？1,000 个、5,000 个呢？

ADR 0002 已经给出两条硬约束：**隔离靠部署形态，不靠引擎代码**；
**每租户必须独立代码副本**（F-01～F-04 四项越权未被拒绝，全部源于共享代码树）。
同时它留了一句「规模化成本未评估：每租户约 300 MiB 内存是空载值，
需要在 P0-00.8 里结合并发与答卷增长核算」。本 ADR 就是补这一笔。

引擎侧还有两个此前没人查过的面：
**引擎默认就在往 `comfortupdate.limesurvey.org` 打请求**，
以及**中文 PDF 用的是不内嵌字形的 CID 字体**。

## 决定

1. **气隙的定义是可执行的，不是声明的**。交付栈的默认 docker 网络是 `internal: true`，
   容器没有默认路由。开机自检脚本实际探测 DNS 与路由表，探测成功即判 FAIL。
2. **端口映射不能当作隔离方案**。docker 的端口映射需要带网关的网络，一挂上出网能力就回来了
   （已实测：默认路由出现、`www.limesurvey.org` 可解析、外网 TCP 返回 301）。
   对外服务必须由客户侧反向代理 ＋ 主机防火墙承担，交付文档不得把「容器没有默认路由」写成唯一保证。
3. **出网通道按清单逐条关闭，并写进开机自检**。必关四类：ComfortUpdate 通知
   （`updatable=false`）、扩展版本自查（两个核心插件停用 ＋ 清空唯一一处 `<source>`）、
   地图题的三个第三方域名（**无配置开关，必须打补丁**）、主题里的 Google Fonts `@import`。
   完整清单与 file:line 见 [私有化交付 §2](../p0/private-deployment.md#2-运行时出网清单气隙必须关掉的全部通道)。
4. **镜像按 digest 交付，不按 tag**。`platform/deploy/private/images.lock` 固定摘要。
   依据是实测到的 tag 漂移：`postgres:16-alpine` 本机摘要与 Docker Hub 当前摘要已不同。
5. **备份件是三件套加清单**：`db.sql.gz` ＋ `upload.tar.gz` ＋ `config.tar.gz`（含 `security.php`）
   ＋ `manifest.txt`（版本、表数、行数、SHA-256）。恢复前先校验 SHA-256。
   **`security.php` 是 sodium 密钥，必须进备份件，因此备份件本身按密文管理。**
6. **恢复顺序固定**：先配置（密钥要早于任何加密字段读写）→ 再 `DROP`＋`CREATE`＋导入 dump
   （不能往已安装的库里直接灌）→ 再覆盖 `upload/` → 最后清 `tmp/runtime/`（schema 缓存）。
7. **规模化形态按成本模型选，不按直觉选**。ADR 0002 决定 2 已证明共置数据库靠授权拦得住
   （越权矩阵 DB-04～DB-14 全部被拒），因此 **共享数据库服务器 ＋ 每租户独立库与账号** 是
   默认形态；每租户一个 mariadbd 只在客户明确要求物理隔离时才用。
8. **ADR 0002 决定 3 收紧为「代码树只读 ＋ 四类路径按租户独占」**：
   必须独占的是 `application/config/`（含 `security.php`、`allowed_hosts.php`）、
   `tmp/`、`upload/`、`plugins/`；代码树本身只要**不可写**就同时消除了 F-01（写入邻居可执行的 PHP）
   与 F-02（互相读取）的写入面。这条已做冒烟验证（见下），但**未达到可上生产的证据级别**。
9. **`MaxRequestWorkers` 必须从默认 150 压到个位数并给容器设内存上限**。
   否则单租户 web 峰值可达约 3.09 GiB，一个租户被打就能拖垮同机邻居。

## 验证

验证栈 `platform/deploy/private/`（独立 compose 项目 `survey-private`，
与 dev / test / tenancy / exam 四套栈无任何共享卷）。

### 离线安装

镜像就位后，起栈、灌码、`console.php install` 全程无外网：59 张表、管理员创建成功、
容器内 `GET /index.php/admin` 返回 302。

| 出网探测 | 结果 |
|---|---|
| `getent hosts www.limesurvey.org` | 返回码 2，无解析 |
| `curl https://1.1.1.1/` | `(7) Failed to connect … after 0 ms`（内核层无路由，不是超时） |
| `/proc/net/route` | 只有直连路由，**无默认路由** |
| 叠加端口映射后同样三项 | 默认路由出现、域名解析成功、外网返回 301 |

**没有证明的**：没有在真正断网的主机上做过（证明的是容器无出口，不是主机无出口）；
没有验证 `docker load` 的离线导入；**没有离线重建 `survey-web` 镜像**。
「镜像已存在」是本次演练的前提，不是结论。

### 备份与恢复

夹具：导入一份 LSS（sid=372723）、激活、25 份答卷、一份 14,848 字节的附件金丝雀。

| 步骤 | 耗时 | 结果 |
|---|---|---|
| 备份 | 1.0 s | db 18,756 B／upload 40,958 B／config 1,645 B |
| 销毁（`down -v`，删四个卷） | 3.2 s | 卷全清 |
| 全新安装 | 15.6 s | 59 表、0 问卷（确认干净） |
| 恢复 | 1.0 s | 三件 SHA-256 校验通过后执行 |

恢复后逐项比对：问卷数、答卷数、**答卷全表内容 MD5**、问卷标题、**附件 MD5**、
**`security.php` MD5** —— 六项全部与销毁前同值，`diff` 无差异。
功能回归：公开问卷页 200、后台 302、RemoteControl `export_responses` 返回 25 条。

规模化：把答卷扩到 **102,400 行**后重做备份，耗时 0.6 s，
未压缩 SQL 15,586,639 B（**152 B/答卷**）。
> 这 10 万行由 25 行自乘得到，gzip 压到 47:1；真实数据一般 5～8:1，外推必须用未压缩值折算。

**没有证明的**：只测了 MariaDB（ADR 0001 决定 5 把 PG 16 定为生产首选）；
没测备份期间仍在填写的一致性；没测跨大版本恢复。

### 开机自检

`platform/deploy/private/preflight.sh`（211 行）。
原始 dev 镜像 ＋ 有出网的网络：**FAIL=7 WARN=5**。
按决定 3 加固后（只改容器内的代码副本，**未动仓库里的 `application/**`**）：**FAIL=1 WARN=1**。

剩下的 1 个 FAIL 是「镜像里带 xdebug」——这是 dev 镜像的真实属性，自检不该放过它；
剩下的 1 个 WARN 是中文 PDF 字体（见已知限制）。
加固后功能回归：后台 302、登录页 200（85 ms）、10.24 万答卷仍在、引擎日志无外联失败痕迹。

### 成本基准（全部实测）

| 项 | 值 |
|---|---|
| 内存：冷启动 / 空载 / 负载中（≈100 rps） | 164.4 / **278.8** / 358.8 MiB |
| 磁盘：代码副本 / 数据库 / `tmp` / `upload` | **519.4** / 156.4 / 72.6 / 0.7 MiB＝**749.1 MiB** |
| 数据库里的固定开销（与数据量无关） | **148.5 MiB**（其中 `ib_logfile0` 占 96 MiB） |
| 每份答卷存储 | **72.6 B**（14 列短值问卷） |
| 容器 / 进程（空载） | 2 / 7 |
| 冷启动 → 首个 HTTP 200 | **5.91 s**（温请求 TTFB 47–53 ms） |

空载 278.8 MiB 与 ADR 0002 的「约 300 MiB」吻合。
但 ADR 0002 的「约 220 MB 磁盘」**只算了数据库与 tmp，没算每租户代码副本**；
把决定 3 要求的独立代码副本算进去，真实值是 **749 MiB，是原估值的 3.4 倍**。

5,000 租户外推（假设见成本模型 §3.1）：

| 形态 | 内存 | 磁盘 | 容器 |
|---|---|---|---|
| 每租户独立 DB（ADR 0002 直译） | 1.37 TiB | 3.54 TiB | 10,000 |
| 共享 DB ＋ 独立库账号 | 645 GiB | 2.84 TiB | 5,001 |
| ＋ 只读共享代码树 | 645 GiB | **369 GiB** | 5,001 |

**代码副本在前两种形态里占总磁盘的 70%～87%**，是唯一值得优先解决的成本项。

### 只读代码树（决定 8 的依据）

把代码卷挂成 `:ro`，另给 `application/config/` 一个独立小卷（实测 272 KiB / 38 文件）：

| 检查 | 结果 |
|---|---|
| 往代码树写文件 | `Read-only file system` —— **F-01 的写入面消失** |
| 后台 / 登录页 / 公开问卷页 | 302 / 200 / 200 |
| `export_responses`（读 102,400 条） | 全部返回 |
| `add_response`（写） | 新 id 102401 |
| `import_survey` ＋ `activate_survey` ＋ `delete_survey` | 全部 OK |
| 资源发布 `tmp/assets` | 正常（71.9 MiB 落在可写卷） |
| 引擎日志 `read-only` / `permission denied` | **0 条** |

### 暂停低活跃租户

停止的租户内存归零、磁盘只少 12 MiB（`ibtmp1` 停机时删除）。
5,000 租户暂停 80%：内存 1.37 TiB → 280 GiB（**省 80%**），磁盘只省 **1.3%**，容器数不变。
代价是 **5.91 s 冷启动**，必须由前置代理托住第一个请求。

## 已知限制与后续

- [ ] **决定 8 的证据级别不够**。只读代码树只跑了冒烟：
      （a）上传安装插件会写进代码树下的 `plugins/`
      （`application/libraries/PluginManager/PluginManager.php:37` 的 `'user' => 'webroot.plugins'`，
      `ExtensionInstaller/PluginInstaller.php:40-43` 直接 move 过去），需要再给 `plugins/` 一个小卷并实测；
      （b）没跑 functional 套件；（c）没验证多个租户真的共用同一个只读卷；
      （d）没验证引擎升级（`UpdateDbCommand`）在只读树下的行为。
- [ ] **交付镜像不可复现**（GAP-1/GAP-2）：`platform/deploy/dev/Dockerfile` 的 `FROM` 无 digest，
      且 `apt-get update` 与 `pecl install xdebug` 都需要联网。生产镜像必须钉死基础镜像 digest
      与 apt 快照源，**并去掉 xdebug**（自检现在就因此判 FAIL）。
- [ ] **真正断网主机上的完整安装演练没做**：包括 `docker load` 导入与镜像离线重建。
      交付前必须补一次端到端。
- [ ] **中文 PDF 可能是空白**。`config-defaults.php:405` 把 `zh-Hans` 映射到 `cid0cs`，
      而 `cid0cs.php` 是 `cidfont0` —— 只带度量、不内嵌字形，PDF 依赖阅读器自备 Adobe-GB1 字体。
      内网 Kylin 机器上未必有。需另备可嵌入的中文 TTF 并处理字体授权。
      **本次只做了文件类型判定，没有端到端生成并在无字体阅读器里打开。**
- [ ] **PostgreSQL 路线整条未覆盖**：成本基准、备份脚本（现用 `mariadb-dump`）、
      恢复流程全部只对 MariaDB 做过。而 ADR 0001 决定 5 把 PG 16 定为生产首选。
- [ ] **地图题的三个域名只能靠打补丁**（`qanda_helper.php:909`、`assets/scripts/map.js:54-57`、`:203/:206`）。
      这会产生需要长期维护的核心补丁，按 SBOM §3.2 的 P-1～P-4 有标注修改与清单义务。
      替代方案是平台侧直接禁用地图题型——建议优先评估这条。
- [ ] **`MaxRequestWorkers=150` 下的峰值内存是线性外推（3.09 GiB），没有实测。**
- [ ] **数千容器规模下 docker 自身的开销没测**。5,000 租户＝5,001～10,000 个容器，
      单机已不现实，需要多节点方案；而「一个进程池服务多租户」与 ADR 0002 的隔离结论直接冲突，
      没有新证据之前不能选。
- [ ] **`tmp/assets` 71.9 MiB/租户** 在只读方案下成了头号变量成本（占 96%）。
      这些是同一份源资源的哈希副本，能否预发布后共享没测；若能，每租户磁盘可再降到约 3.6 MiB。
- [ ] **信创：ARM64 已有实测证据，OS 与数据库两维一项都没测，国密是缺失而非待测。**
      选定组合为 Kylin V10 SP3（ARM64/鲲鹏 920）＋ OceanBase 4.2 MySQL 模式。
      本机是 ARM64，ADR 0001 的 848 用例与本次全部演练都跑在 ARM64 上，
      但这只证明 linux/arm64 ABI 可用，不证明 Kylin 内核与鲲鹏微架构。
      数据库侧已定位到具体探测点（`InstallerConfigForm.php:343/444/469-470`，
      且 `getMySqlConfigValue` 吞异常返回 null，**不支持这些变量的库会静默通过检查**），
      但没有国产库可测。国密 SM2/SM3/SM4 引擎完全没有（加密走 libsodium），属改造而非配置。
      完整清单见 [私有化交付 §6](../p0/private-deployment.md#6-信创目标组合与认证清单)。
- [ ] 决定 9（压 `MaxRequestWorkers`、设容器内存上限）尚未落到交付 compose 里。
- [ ] 备份件加密与异地保存未设计。
