# ADR 0015：答卷导出作业（WP-06 切片 06.2）

- 状态：已实现（2026-09-22），待集成审查
- 关联需求：R06-02 Excel/CSV 导出（中文、缺失、选项码、多选展开、防公式注入）；R06-07 附件**清单**（不打包文件本身）；
  R06-08 中"下载器禁止 SSRF"（本切片从不抓取答卷里的 URL）；R06-06 中"大批任务可恢复"的作业骨架；
  R06-09 中"统计权限不能下载明细"
- 关联：ADR 0013（作答按页经网关读取、字段字典）、契约 `platform/contracts/response-read-v1.md`
- 蓝图 API：`POST /v1/exports | filterSnapshot、format、templateVersion | jobId、expiresAt；下载再次授权`
- 验收：30 万答卷分批导出无漏重；导出中撤权下载被拒；恶意图片 URL 不访问内网

## 背景

06.1 的明细是"投影分页＋按页经网关补作答"。导出要把整份问卷（可达 30 万答卷）写成文件：不能在一次请求里做完，
不能把所有行放进内存，也不能因为导出期间有新答卷写入而漏行或重行。平台不持有引擎口令，作答只能经网关读取（ADR 0013）。

## 决定

### 1. 作业模型：创建即定水位线，快照物化成有序键表

- `POST` 只做权限判定、冻结"导出计划"、落一行作业（`queued`），返回 202 与 `jobId`。
- **水位线 = 作业创建时刻 `created_at`**。投影行自带 `created_at`（插入事务的开始时刻）。创建时已可见的行，
  其 `created_at` 必然早于作业创建，因此一定在快照里；之后才出现的行 `created_at` 晚于水位线，一定不在。
  唯一的模糊地带是创建瞬间仍在途、之后才提交的事务——它们要么整体在、要么整体不在，不会重复。
  否决"记录每个版本的最大键"：引擎事件可能乱序到达，较小的答卷号晚到会被错误地算进快照，
  崩溃恢复后重跑还会得到不同的集合。
- 快照**物化**到 `response_export_item`：按 (版本, 代次, 答卷号) 键集翻页读投影（经 engine 模块的
  `ResponseProjectionQuery`，只多了一个"创建时刻不晚于水位线"的条件），逐页写入并编号 `seq = 1..N`。
  之后的一切都按 `seq` 走：导出集合在物化完成后固定，**无漏、无重**由主键 `(tenant, job, seq)` 与
  `(tenant, job, 版本, 代次, 答卷号)` 唯一约束兜底。状态（进行中 / 已完成 / 已删除）取物化那一刻的值，随行存下。
- **导出计划**冻结在作业行（`plan` jsonb）：每个来源的版本号、(实例, sid)、当时的最近代次、字段字典。
  导出期间重新发布出现的新版本不进入本次导出；表头因此在重跑、恢复时逐字节相同。
- **可恢复分批**：每批 `batchSize`（默认 500，等于网关单次读取上限）个 `seq`，经网关读作答、遮蔽、
  编码成一个"分片"写入文件存储，然后在一个事务里把检查点 `next_seq` 前移。崩溃发生在写分片之后、
  前移检查点之前时，重跑同一批会覆盖同名分片——**重试幂等**。全部分片完成后按序拼成最终文件、算 SHA-256、删除分片。
- **租约**：同一作业同一时刻只有一个执行者。认领用 `FOR UPDATE SKIP LOCKED`，写入随机 `lease_token` 与 `lease_until`；
  每次前移检查点都带 `lease_token = :mine AND status = 'running'` 条件并续租，条件不成立（被取消、租约被接管）即停止。
  进程死掉后租约过期，其他副本（或本进程下一轮）从检查点接着做。
- 失败：单批失败（网关不可达、引擎报错）累计 `attempts` 并按退避重排；达到上限转 `failed`。
  权限在每批开始前复核一次：创建者已失去导出权限、或"可见敏感字段"与创建时不同，作业立即 `failed`（`permission_changed`），
  避免同一文件前后遮蔽口径不一。
- 状态：`queued → running → completed | failed | cancelled`，以及到期后的 `expired`。作业行不删除（审计线索）。
- 幂等创建：可选请求头 `Idempotency-Key`；同一创建者同一键返回原作业，参数不同则 409。

### 2. 文件放在哪里

- 平台侧对象存储抽象 `ExportFileStore`（`create / open / size / delete / deletePrefix`），键形如
  `<租户>/<作业>/part-000000000001`、`<租户>/<作业>/export.xlsx`，只允许 `[a-z0-9.-]` 与 `/` 分段，拒绝 `..`。
- 开发与测试用本地文件系统实现（`platform.response.export.storage-dir`），写入先写临时文件再原子改名，
  读者永远看不到半个文件。生产可替换为对象存储（S3 / OSS / MinIO）实现，接口不变。
- **静态加密：本切片不做应用层加密**，要求部署层提供（磁盘加密 / 对象存储服务端加密）。理由：流式 AES-GCM
  在 JDK 里解密时会缓冲整个密文才校验标签，30 万行文件会破坏"内存有界"；分块加密需要自定义容器格式，
  与"可替换为对象存储"的方向重复。补偿措施：文件短期保留、到期即删、下载必须再次授权、文件名不含个人数据。
  后续若等保要求应用层加密，在 `ExportFileStore` 装饰一层分块 AES-GCM，不影响其余代码。

### 3. 保留与到期

- `expiresAt = 创建时刻 + retention`（默认 72 小时，`platform.response.export.retention`），创建时即返回。
- 后台清理：到期作业删除全部文件与快照行，状态置 `expired`；下载到期作业 410。快照行在作业完成时即删除，
  只在作业进行中占用空间。

### 4. 下载再次授权

- `GET /v1/exports/{jobId}/download` 每次都重新判定：作业只对创建者可见（他人、他租户 404）；
  创建者此刻必须仍有 `export-raw-responses`；若文件含敏感明文，还必须仍有 `view-sensitive-fields`。
  任一不满足 → 403，即使作业 id 有效、文件已生成。然后才看状态：未完成 409、已到期 410。
- 响应 `Cache-Control: no-store`、`Content-Disposition: attachment`，文件名只含问卷 id 与作业 id；每次下载写审计。

### 5. 格式

- 通用分片格式：每行一个 JSON 字符串数组（已遮蔽），与最终格式无关；最终文件由 `ExportFormat` 实现流式写出。
  这是 SPSS SAV、Word/PDF 模板等后续格式的扩展点（`templateVersion` 本切片只接受空或 `default`）。
- `csv`：一个 ZIP，内含 `responses.csv`、`fields.csv`（数据字典）、`attachments.csv`（附件清单），均为 UTF-8 带 BOM、CRLF。
  以 `= + - @`、制表符或回车开头且不是纯数字的单元格前加 `'`，防公式注入。
- `xlsx`：只用 JDK 手写的最小 OOXML（`[Content_Types].xml`、工作簿、三个工作表、最小样式），全部内联字符串，
  不产生公式；单元格超过 32767 字符截断；行数超过 Excel 上限时作业失败而不是截断。
- 两种格式都把 ZIP 条目时间固定为常量，同样的数据产生**逐字节相同**的文件（崩溃恢复测试依赖这一点）。
- 表头两行：第一行列代码（固定列＋`题目代码[子题]#尺度`），第二行中文标签。多个版本的同一列按列代码合并。
- 敏感列：按创建时判定的 `ResponseFieldPolicy` 遮蔽；数据字典标出哪些列被遮蔽。

### 6. "扩展"数据与附件清单

- 字段字典只认识引擎答卷列。扩展副表作答（平台侧 C 档题型）压不进这张按字典出列的表——副表是行×列、
  每份答卷行数不同。切片 06.4 给它单列一张长表，见**增补二**。
- 附件：文件上传题（题型 `|`）的作答是引擎写的 JSON 数组。清单逐个列出文件名、大小、扩展名、引擎存储名，
  以及值里自带的 `sha256`（有则填，没有留空）。**导出从不抓取任何 URL**：作答里出现的图片链接、附件里的地址
  都只作为文本输出，平台不发起任何外部或内网请求（R06-08 的"URL 转图"留给后续切片，并必须走带白名单的下载器）。

### 7. 网关

- 不新增端点。现有 `POST /v1/responses/read` 已经是批量接口（每次 ≤ 500 个答卷号，网关内按间距 < 200 分段调用
  `export_responses`），导出按 `seq` 取出的答卷号本来就是密集、有序的，一批 500 个对应 3 次引擎调用。
  按区间读取的变体只能省下这 3 次调用中的 2 次，却要新增一套契约与真引擎验证，本切片不做。

## 验证

- `ResponseExportConsistencyTest`：导出期间后台持续写入（含更小答卷号、另一版本、另一代次），文件里恰好是创建时已有的行，无重无漏。
- `ResponseExportResumeTest`：批中途模拟进程死掉（租约不释放、下一个分片内容损坏），租约到期后恢复，CSV 与 XLSX 都与一次跑完的文件 SHA-256 相同；网关暂时失败退避重试同样逐字节相同；取消、到期 410、防公式注入。
- `ResponseExportAccessTest` / `ResponseExportApiTest`：统计查看者 403；遮蔽；完成后撤权下载 403；只丢"查看敏感字段"时下载明文文件 403；导出中撤权作业 `failed(permission_changed)`；他人 404；幂等键；202/Location/no-store。
- `ResponseExportTenantIsolationTest`：跨租户 404、执行者认领不到；两张新表的裸 SQL 读写被行级安全拒绝；运行期账号不能删作业。
- `ExportFormatTest`：XLSX 各部件 XML 合法、只有内联字符串；CSV BOM/CRLF/引号/公式防护；附件清单只解析不抓取。样例 `target/export-sample.xlsx` 经 openpyxl 3.1.5 与 LibreOffice 读回一致。
- `ResponseExportScaleTest`：默认 2 万行随套件跑；`-Dexport.scale.rows=300000` 实测 30 万行：600 次网关读取（每次 500）、导出 18.4 秒、文件 3.6 MB、采样堆增长峰值约 113 MiB（含未回收垃圾）。

## 残余风险与后续

- [ ] 敏感列按列名合并判定：不同版本同名列只要有一个版本标了敏感，所有版本的该列都遮蔽（只会多遮、不会漏遮）。

- [ ] 应用层静态加密（见决定 2）。
- [ ] 物化期间答卷状态可能变化：快照记录的是物化那一刻的状态，"按状态筛选"对极少数在途行可能与创建时刻不同。
- [ ] 作答值在批次读取时从引擎取：导出期间被修改的进行中答卷，取到的是读取时刻的值。平台没有作答的历史版本，无法做到按时刻一致。

- [ ] 批量附件 ZIP（R06-07 全量）、URL 转图（R06-08）、Word/PDF 模板（R06-05/06）。

## 增补一（第五波，切片 06.3）：SPSS 系统文件（SAV）导出

- 状态：已实现（2026-09-23），待集成审查
- 关联需求：R06-03 SPSS/SAV 与变量字典（验收：变量标签／值标签／缺失值可在兼容工具读回并核对）

决定 5 留的扩展点这次用上了：`ExportFormat` 加一项 `sav`，作业模型、分片格式、租约、崩溃恢复、
下载再次授权全都不变，只多一个 `ExportFormat.Writer` 实现。迁移只放开 `response_export_job.format`
的取值约束（`V601`）。

### 一、包的构成，而不是单个 .sav

`sav` 产出一个 ZIP（扩展名 `sav.zip`），里面四个文件：

| 文件 | 内容 |
|---|---|
| `responses.sav` | 数据集本身，变量标签与值标签写在 SPSS 自带的字典里 |
| `variables.csv` | 变量字典的可读副本：SPSS 变量名 ↔ 原始列代码、数值还是文本、宽度、**完整**选项表 |
| `fields.csv` / `attachments.csv` | 与 CSV 包里的同名文件逐字节同构 |

否决"只给一个 .sav"：SPSS 的字典放不下两样东西——附件清单（R06-07 的清单部分本来就属于每次导出），
以及挂不进 SPSS 的那部分值标签（见下）。丢掉它们等于让 SAV 用户比 CSV 用户少拿到数据。
`variables.csv` 同时解决"变量名被消毒过、对不回列代码"的问题。

### 二、变量怎么定

- **两遍扫描**。SPSS 的字典写在数据之前，而字符串变量的宽度只能由最宽的取值决定。分片本来就支持
  重放（`ExportSheet.RowSource` 可以重复调用），于是第一遍只统计每列的宽度与"是不是全是数字"，
  第二遍写数据。任何时刻只持有一行，内存占用与答卷数无关，代价是分片多读一遍。
  否决"一律按 255 字节定宽"：300 列 × 255 字节 ＝ 每条记录 76 KiB，30 万答卷的文件会膨胀到不可用。
- **什么列算数值**：该列有取值、**所有**非空取值都是数字、**且**（没有选项表，或选项代码也全是数字）。
  两条额外的闸门：有效数字超过 15 位的不算（放进双精度会悄悄丢精度），有前导零的不算
  （`007` 是代码不是数量，变成 `7` 就再也对不回去）。选项代码不全是数字时整列按文本导出，
  否则值标签会与取值对不上——宁可少一个数值变量，不要一份对不上的字典。
- **字符串宽度** ＝ max(观察到的最宽取值, 最长的选项代码, 1)，上限 255 字节。把选项代码也算进去是
  必须的：SPSS 比对值标签时只看变量宽度那几个字节，变量比代码窄就会把两个不同的选项认成同一个。
- **变量名**：列代码里的 `[ ] # ~` 都不是合法的 SPSS 名字字符，消毒成下划线，不能以数字开头，
  最长 64 字节，忽略大小写去重。原始列代码原样留在 `variables.csv`，不丢。
  旧式 8 字节短名一律生成 `V1…Vn`，长名走扩展记录 7/13。

### 三、做不到的与刻意不做的

- **值标签只能挂在数值变量或不宽于 8 字节的短字符串变量上**（SPSS 格式本身的限制）。
  固定列 `state`（`engine_completed` 16 字节）与 `answersstatus`（`available` 9 字节）因此挂不上，
  它们的完整取值表在 `variables.csv` 里。挂不上时一个都不写，不写"一半取值有标签"的字典。
- **超过 255 字节的取值截断**，且只停在 UTF-8 字符边界上（不会把一个汉字劈成两半）。
  "超长字符串"（扩展记录 7/14）本切片不做。
- **缺失值**：数值列的空格写系统缺失（SYSMIS ＝ `-DBL_MAX`），字符串列的空格是空串。
  不声明用户自定义缺失值——"为什么没有作答"已经由固定列 `answersstatus`（已删除／已被替换的代次／
  引擎当前表里没有）逐行说清楚，再编一套缺失码只会多一份口径。
- **不压缩**。压缩只省磁盘，却要在写出时维护一条字节码流，与"逐字节可复现"和"内存有界"都相冲。

### 四、逐字节可复现

SPSS 文件头里有创建日期与时间。这两个字段写成**常量**（`01 Jan 80` / `00:00:00`），
和 ZIP 条目时间一样——否则崩溃恢复后重跑得到的文件与一次跑完的不同，决定 1 的"重试幂等"就没法验证。

### 五、防公式注入

二进制的统计格式自己不执行公式，但 SPSS / PSPP 能把数据集另存为 xlsx 或 csv，那一步又回到会执行
公式的地方。所以防护统一提到最外层：`ExportCellGuard` 现在是 CSV 与 SAV 共用的单元格出口，
按格式开口子的做法被否决。数值列不受影响——它们在判定阶段就已经确认是纯数字，写的是双精度。

### 六、验证

- `SavExportFormatTest`（纯单元，9 项）：包的构成与 `variables.csv` 的表头与内容；文件头（布局码、
  未压缩、UTF-8、记录数、`nominal_case_size`）；每列一个变量、长名是消毒后的列代码、标签是中文表头；
  数值／文本判定；值标签挂在数值与短字符串上、宽列上没有；单元格读回（SYSMIS、按字符边界截断）；
  防公式注入；同样的输入逐字节相同。读回用 `SavReader`——测试里按格式规范另写的一份最小解析器，
  不复用被测代码的任何常量。
- `ResponseExportSavTest`（5 项）：整条作业链路（建作业 → 后台跑完 → 下载）产出的包，
  以及包里的变量标签、值标签、数值答卷号、被挡住的公式文本、挂不上值标签的列在 `variables.csv` 里。
- `ResponseExportResumeTest`：崩溃恢复的"逐字节相同"断言加跑一遍 `sav`（原本只有 `csv`、`xlsx`）。
- **第三方读回**：`target/export-sample.sav` 用 pyreadstat 1.2.7（ReadStat C 库）读回，
  变量名、中文变量标签、值标签、`F8.2`/`A16`/`A19`/`A255` 格式、UTF-8、3 条记录、SYSMIS→NaN、
  按字符边界截到 253 字节、以及被加了单引号的公式文本，逐项与预期一致。
- 平台全量 1010 通过、0 失败 0 错误。

### 七、这一项没有动到的

网关与引擎一行都没改：SAV 只是平台把已经取到的作答换一种文件格式写出来。
导出依然从不抓取任何 URL。

## 增补二（第七波，切片 06.4）：扩展副表作答进导出

- 状态：已实现（2026-09-24），待集成审查
- 关联需求：R02 的 C 档题型（ADR 0006 决定 4）在导出里可读；契约 `question-extension-tables-v1`、
  `response-read-v1`「扩展表作答」
- 前置：ADR 0018 的网关↔插件通道已把 `extensionAnswers` 送到平台，但只到平台，没进文件

### 一、不定行数怎么落进二维表

副表作答是**行×列**，而且每份答卷的行数不同：表格题填了几行、货架题取了几件、心理实验做了几个
试次，都是作答时才产生的。导出文件是二维的，必须选一种落法。

**决定：单列一张长表 `extensions`（工作表「扩展表作答」），一个单元格一行。**
固定十列，与列字典无关：

```
version  sid  responseid  generation  question  structureversion  isvalid  rowindex  column  value
```

一份答卷一道题的一行单元格 → 若干行，按 (题目, 行序, 列序) 排；`rowindex` 即副表的行序号（从 0 起）。
分析时按 `responseid + question + rowindex` 透视一次就还原成原来的表格。

否决掉的两种：

- **宽表加序号后缀**（`QTABLE[1][item]`、`QTABLE[2][item]`…）：需要一个「最多多少行」的约定，
  而那个上限在冻结表头时并不知道——字段字典是发布时冻结的，副表行数是作答时才产生的。
  硬压要么截断作答，要么让列集随数据漂移。这与网关侧「`extensionAnswers` 单列一段、不并进 `values`」
  是同一条理由（ADR 0018），在导出这一侧同样成立。
- **每个副表行一条记录、列代码横着展开**：可读性最好，但表头需要一份**冻结的列字典**，而平台手上
  没有。列字典是网关按主题算出来的（`pubgw/questions/theme_specs.py` 的 `side_columns`）：
  只有 `mjy-repeating-table` 的列就是定义快照里的 `themeOptions.columns`，另外七个 C 档主题的列
  由热区坐标、循环评价的对象与维度、图片 PK 的配对、货架的商品、文字点睛的片段、心理实验的试次、
  KANO 的功能点各自推出来。在平台再写一遍这八套推导，就是契约 `question-extension-tables-v1`
  已经警告过的那种重复（「两边不一致等于发布出去才发现」）；绑定记录里的 `sideTables[].columns`
  平台又没有存。**宁可让分析者透视一次，也不要一份对不上的列字典。**

这个形状还顺带解决了结构版本 `"0"`（列定义无从考证）那一档：契约要求读端「不得猜测列字典，
只能按 `column_code` 原样呈现」——列代码在长表里是**取值**而不是表头，原样呈现是天然的。

代价如实记下来：**文件行数 ＝ 单元格数**，不是答卷数；分析前要透视一次。

### 二、一行单元格都没有的那一题仍然占一行

契约第三节第 1 条：校验没过时单元格表是空的、状态表记 `is_valid=0`，而引擎答卷列里还留着作答者的
原文。导出必须让人一眼看出「这条不可信」，而不是看到一张空表就以为没填。所以 `rows` 为空时仍写
一行，`rowindex`／`column`／`value` 都空，`isvalid` 照写。校验通过但确实是零行的，同样留一行
（`isvalid=true`），两者靠 `isvalid` 区分。

### 三、敏感副表题遮蔽

副表题的作答在引擎答卷表里是一列 JSON 信封，那一列按 `ResponseFieldPolicy` 遮蔽。**同一份数据不能
因为换了张表就明文出去**：`ExportRowEncoder` 按题目代码判定敏感（敏感标记来自定义快照，与那一列
信封是同一个来源），遮蔽走 `ResponseFieldPolicy.cell`，掩码与 `apply` 逐字相同。

### 四、其余全部不变

- 分片格式只多一个前缀字母 `E`（`R` 答卷、`A` 附件、`E` 副表单元格），仍是每行一个 JSON 字符串数组，
  仍是"已遮蔽后才落盘"。作业模型、水位线、租约、检查点、崩溃恢复、下载再次授权一律不变。
- 列集固定，与作答无关，因此表头在重跑、恢复时逐字节相同（决定 1 的前提没有被削弱）。
- 内存有界的口径没有变，但要说准：**收尾**阶段逐格流式写出，任何时刻只持有一行，与答卷数、
  副表行数都无关；**分批**阶段和以前一样在内存里持有一批（默认 500 份答卷）的编码结果，
  这一批的上界因为副表而变大了——每份答卷每道副表题最多 500 行（插件的
  `MjyRepeatingTableValidator::HARD_MAX_ROWS`）乘以列数上限。仍然与**总**答卷数无关，
  但 `batchSize` 对内存的杠杆变长了。真要压，调小 `platform.response.export.batch-size`。
- 三种格式都自动带上这张表——CSV 包多一个 `extensions.csv`，XLSX 多一个工作表，SAV 包多一个
  `extensions.csv`。**没有副表题的问卷也有这张表**，只有表头：附表在不在不该随数据变。
- 防公式注入照旧在最外层（`ExportCellGuard`），新列不开口子。
- **导出依然从不抓取任何 URL**：副表单元格里出现的地址只作为文本输出。
- 不需要新迁移：副表题名单由定义快照里的主题名推出（`ExtensionQuestions`，与字段字典判定
  「这一列是整块 JSON 信封」用的是同一个主题集合），冻进作业计划的 `plan` jsonb。
  06.4 之前建的作业计划里没有这一段，反序列化成空表——**旧作业不会因为升级而改变文件内容**。

### 五、读取侧

`ResponseAnswerSource.read` 改成收一个 `AnswerQuery`：代次与副表题目代码要么都给要么都不给
（契约要求，缺代次网关一律 400），这个约束在 `AnswerQuery` 就地判，不等网关退回来才发现。
应答里的 `extensionAnswers` **失败即关闭**：点了名却没有这一段、出现没点名的答卷或题目、
形状不对，一律视为应答不可信（503），绝不当成「这批没有副表作答」。

一次最多点名 50 道副表题（契约上限）。超过的版本在**建作业时**就拒绝，而不是分几次读：
分多次读会让同一份文件里的副表来自不同时刻，与「作业创建即定水位线」相冲；悄悄少读几道题更不行。

### 六、验证

- `ResponseExportExtensionsTest`（7 项）：一个单元格一行的行序与列序；闸门没过时仍留一行；
  敏感题的单元格被遮蔽（`project_manager` 角色）；单元格里的公式文本被挡住；
  计划里冻结的题目名单与代次确实传给了网关；没有副表作答时这张表仍在；结构版本 `"0"` 的列代码原样落下。
- `HttpResponseAnswerSourceTest`（新增 6 项）：不点名副表时请求体一字不变；点名时带上代次与题目；
  应答解析；缺这一段、答卷号／题目没点过名、`rows` 形状不对一律不可信；空对象是合法应答；
  只给题目不给代次在本端就地拒绝。
- `ExtensionQuestionsTest`（4 项，纯单元）：只认副表主题、按定义顺序、去重、覆盖全部八个 C 档主题。
- `ResponseExportResumeTest`：场景改成带副表作答且**各份答卷行数不同**（0–3 行，另有一份没过闸门），
  崩溃恢复的「逐字节相同」断言因此覆盖这张长度不定的表；另加一项专门钉住这张表确实有内容——
  一张空表在两次跑法里都是空的，照样「相同」，只看 SHA-256 会漏。

### 七、这一项没有动到的

- **明细列表（`GET /v1/surveys/{id}/responses`）仍不带副表作答**：只有导出走这条路。
  明细是分页的逐行视图，副表塞进去等于在一行里嵌一张表，形状要另议（`ResponseRow` 的 `answers`
  是扁平映射）。
- 网关与插件一行都没改。
- 列字典（列标签、类型、取值集合）仍然不进导出：见第一节的取舍。要它就要在平台重写一遍八套
  主题推导，或者让发布回执把 `sideTables[].columns` 存进平台——后者是更正的路，属于另一片。
