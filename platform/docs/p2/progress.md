集成时修复：
- **CRITICAL：飞书事件回调是 CBC 填充预言机**——未签名请求跳过验签却仍用调用方给的 IV 解密，且各种失败返回不同状态与消息，匿名方不知密钥即可逐字节解密并伪造"成员离职"事件。现在任何解密之前先验签（握手也一样），所有取决于请求内容的拒绝统一为同一个 401 与同一段响应体（原因只进服务端日志）。发现于合并后的独立安全审查，修复前未推送。
- 共享 e2e 驱动 `Database` 的容器参数改为可选（此前我的改动弄坏了逻辑与答卷读取两个驱动）；答卷读取 runner 跟随容器前缀。
- 引擎测试栈切换 `TEST_DB` 时重启 web 容器：opcache 按时间戳隔几秒才重新校验，紧接着的请求会用上一种数据库的配置（顺序相关的偶发失败）。

### WP-03.3／03.4：计分与双执行比对（已完成）

**计分（03.3）** 接在 03.1／03.2 之上，不另起炉灶：顶层 `scoring` 只被展开成本已有的 DSL——
按选项／子题给分展开成 `if(引用 == "代码", 分数, 0)`，数值题展开成 `coalesce(引用, 0) * 权重`，
总分是 `sum(…)`，分段是按上界嵌套的 `if`，每个分段的文案是一道条件为 `<CODE>B == "<分段代码>"`
的说明题——再走同一条 parser → types → graph → emit。所以「按分数分支／展示结果」就是普通的 v2
条件与文本引用，没有新机制。契约见 survey-logic-dsl-v1 第 6 节。

生成的题追加在一个**新的末尾题组**里。这不是随手放的：该组不带条件，分数就不会被别人的题组条件
连带清空；排在最后也让「只能引用前面的题」自动成立。代价是**前面的题不能引用分数**
（`E_EXPR_LATER_PAGE`），作者要按分数分支就得把那道题放进结果页或自己写条件。

转义按 03.2 的做法收口，但**加了一条更强的性质**：生成的表达式里一个字符的作者自由文本都没有——
只有数字、题目引用，以及平台已校验过字符集的选项／子题代码与分段代码。作者的自由文本（分数标题、
分段文案）全部落在题目的 text 上，由已有的模板路径转义。所以计分不需要一套新的转义规则。

**双执行比对（03.4）** 是本片的主交付。第 4 节的语义现在有两份独立实现：`pubgw/logic/evaluate.py`
直接在语法树上按契约求值，真引擎的 ExpressionManager 跑 `emit.py` 编出来的 ExpressionScript。
解释器**刻意只实现契约、不模仿 PHP 的类型杂耍**——引擎在契约之外的脾气正是比对要暴露的东西，
两边一起装傻就白比了。

分歧要能指出是哪一侧错，靠的是每条用例自带的、照契约**人工写下**的期望值：引擎报错判编译器；
分歧时谁合期望谁对；两边一致但都不合期望判 `both`；没有期望值判 `unknown` 并且**不许算通过**。

注入答案这条路有个要害：`_GetVarAttribute` 读 `.NAOK` 时，题目 `relevanceStatus` 的**缺省是 0**，
不显式置位的话每个引用都读成空串，比对会变成「两边都是空，恭喜全对」。`logic_parity.php` 每条用例
都把全部题目置为相关，再把该隐藏的置 0——这正好就是契约的「隐藏即空」。

结果（`run-publish-gateway-parity.sh`，双库各跑一遍）：**48 条表达式级用例（12 处表达式 × 4 份答案
向量），48 条都带期望值，mysql 与 pgsql 各 48/48 一致且合期望，零分歧。** 归责 platform／compiler／
both／unknown 均为 0。

「全对」本身证明不了比对还能报错，所以另有两道反向对照，都在脚本里常驻：
- **变异对照**：故意把编译产物改坏一次（`<=` 换 `>=`）、把平台的值谎报一次，比对必须抓住，
  并且判对是哪一侧——双库均通过；
- **场景级锚定**：再跑两次真实 HTTP 作答，引擎**真正存进答卷表**的分数与分段（9/MID、3/LOW）
  同平台算的逐一相等，证明注入会话那一套不是自说自话。

发布链路上改了一处：`Publisher.publish` 在校验之后、导入之前把计分展开一次，之后的回读校验、
字段映射、主题检查都按展开后的定义来。不改的话引擎里的分数题会被回读校验报成
`E_CODE_UNEXPECTED`（第一次真跑就是这么失败的）。

#### 复查修正（同片内）

复查报出、协调者独立复现的一条问题：`_reference_text` 把题目 UUID 插进 `q("<uuid>")` 时没有任何
字符集约束，`model.py` 的 `_text()` 对 `uuid` 只要求非空字符串。UUID 写成
`X") + 999, 0) * 1, sum(1` 就能从字符串字面量里逃出来。

**定性：不是提权。** 生成的文本随后由标准 v2 解析器重新解析，走同样的类型检查、引用检查与环检测，
而作者本来就能直接写 v2 DSL 表达式——注入者没有拿到他原本没有的能力。真正坏掉的是两件事：
(1) **正确性**：`_check_item` 校验的是原始引用，渲染出来的文本却可能指向另一道题；
(2) **不变式**：契约 §6 与 `scoring.py` 顶部都声称「生成的表达式里没有一处作者的自由文本」，
UUID 不受限时这句是假的，而且是潜伏危险——将来只要有一个插值点不再被重新解析，它就变成真注入。

修法取根治那条：在 `model.py` 的**解析期**给所有 `uuid`（问卷、题组、题目、子题、计分表）加字符集
`^[A-Za-z0-9][A-Za-z0-9_-]*$`、最长 128，一次关掉整类问题。取值范围同时容纳现存两种写法——JSON
fixture 里的标准 UUID 与 Python 单测里的 slug（`q-single`、`sq-m2`、`sq-{code}-{scale}`、`q-{code}`），
全仓 127 个 fixture UUID 与全部单测 UUID 无一被打死。各插值点（UUID、题目代码、子题／选项代码、
分段代码、分数代码）另加一层 `ScoringError` 断言作为纵深防御，让那句不变式成为本模块**自己**保证的，
而不是依赖上游没被改坏。契约新增 §8 写明这条约束与上面的定性。

同批处理的另外三项：
- **groupTitle 静默丢失**（MEDIUM）：多份计分表共用一个计分组，先前只取 `scoring[0].group_title`，
  其余静默丢弃。改为不一致即报 `E_SCORING_GROUP_TITLE`；一致时仍合并进同一组。补了「两个 score
  各有不同 groupTitle」与「两个 score 同 groupTitle 真的展开成一组」的用例——原有的
  `test_two_scores_may_not_share_a_code` 用的是冲突代码，根本走不到展开这一步。
- **`Infinity`/`NaN` 被接受**（MEDIUM）：`json.loads` 默认认这三个字面量，会被渲染成 `inf`/`nan`
  写进表达式再被引擎当标识符查。`_number()` 显式拒绝非有限浮点数。
- **`evaluate.py` 的 `ANY`/`CHOICE`/`TEXT` 死导入**（LOW）：删除。

四条都先写了能复现的失败用例并亲眼见红（UUID 三条 `DefinitionError not raised`、
`ScoringError` ImportError、`E_SCORING_GROUP_TITLE` 未报、三条非有限数值未拒）。

  矩阵/双尺度不在本批。**恢复会顶掉未发布的草稿改动且不留备份**——这是「丢弃改动回到上一版」的正常
  语义，但前端必须有明确二次确认。
- **题型**：剩 9 类中 R02-03 卡平台字典服务（省市区树数千节点不能塞题目属性）、R02-20/21/25/26/32/39/41
