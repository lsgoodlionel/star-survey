# 批量文本导入格式（WP-01 01.1，需求 R01-02）

把一段纯文本批量变成题目：**先预览、后落库**。解析结果、识别到的题型、认不出来的行，
全部在创建之前回给作者，由作者逐题取舍；坏行只记问题、不中断整批。

实现：`platform/services/business/src/main/java/cn/mjy/platform/survey/QuestionTextParser.java`（解析）
与 `QuestionImports.java`（编号与并入草稿）。

## 一、写法

```
1. 您的性别？[单选]
A. 男
B. 女

2. 平时用到哪些功能？【多选，必答】
A. 搜索
B. 收藏
C. 分享

3. 请写下您的建议
   [多行文本]
```

| 行 | 规则 |
|---|---|
| 题干行 | 以 1–4 位数字加 `.` `、` `)` `）` `:` `：` 开头；其余部分是题干 |
| 标签 | 题干行**结尾**的 `[…]` 或 `【…】`；内部用逗号、顿号、斜杠或空格分隔 |
| 选项行 | 以**单个**字母加 `.` `、` `)` `）` 开头，或以 `-` `*` `•` `·` 加空格开头 |
| 题干续行 | 题干行之后、第一个选项之前的普通行，按换行接到题干上 |
| 空行 | 忽略 |
| 其它 | 记一条 `unrecognized_line`（带行号），**不中断整批**，也不静默丢弃 |
| 超长行 | 超过 4000 字的行在跑任何正则之前挡掉，记一条 `line_too_long`（几个正则都带回溯，超长行会退化成平方复杂度） |

数字开头的一律当题干行，字母／符号开头的才是选项——两种标记必须分开，否则无从区分。

## 二、标签

题型标签（认中英两种写法）：

| 标签 | 引擎题型 | 吃选项 |
|---|---|---|
| 单选 / 单项选择 / radio | `L` | 是（≥2） |
| 多选 / 多项选择 / checkbox | `M` | 是（≥2） |
| 填空 / 单行文本 / 文本 / text | `S` | 否 |
| 多行文本 / 长文本 / 简答 / textarea | `T` | 否 |
| 评分 / 量表 / rating | `5` | 否 |
| 排序 / ranking | `R` | 是（≥2，写成子题） |
| 日期 / date | `D` | 否 |
| 说明 / 说明文字 / note | `X` | 否 |

另有必答标记：`必答` / `必填` / `required`。

**没写题型时按选项有无推断**：有选项＝单选，没选项＝填空；预览里 `typeInferred` 为 `true`，
作者一眼能看出这是推断而不是他写的。

## 三、编号与顺序

- 题目代码由服务端分配：`Q1`、`Q2`……，起点是**当前草稿里已用过的 `Q<数字>` 代码的最大值加一**，
  因此不会与草稿里既有的代码撞车。
- 选项代码按位置生成：`A1`、`A2`……；排序题的选项是子题，代码为 `SQ001`、`SQ002`……
- 预览与落库读同一份原文、走同一条解析与编号，所以**预览里看到的题号、顺序、代码就是落库后的结果**；
  中途有人改了草稿时，乐观锁会把这次导入挡成 409，绝不按过时的编号写入。

## 四、校验与错误码

原文层面（整批拒绝，400 `invalid_request`）：原文为空、超过 256 KiB、超过 5000 行、超过 500 道题。

逐题的阻断性问题（题目仍出现在预览里，但 `importable` 为 `false`，被选中时 422 `invalid_import`）：

| 错误码 | 含义 |
|---|---|
| `unknown_tag` | 认不出的标签 |
| `ambiguous_question_type` | 一道题写了多个题型 |
| `blank_question_text` | 题干是空的 |
| `question_text_too_long` | 题干超过 2000 字 |
| `too_few_options` | 需要选项的题型不足 2 个选项 |
| `too_many_options` | 超过 200 个选项 |
| `options_not_allowed` | 不吃选项的题型却带了选项（**不丢弃**，明说让作者改题型或删选项） |
| `blank_option` / `option_text_too_long` / `duplicate_option` | 选项为空 / 超过 500 字 / 重复 |

整批层面的问题（不属于任何题目）：`unrecognized_line`、`line_too_long`，都带行号。

## 五、接口

```
POST /v1/surveys/{id}/import/preview   {"text": "…"}                    → 预览，不写库
POST /v1/surveys/{id}/import           {"expectedVersion": 1,
                                        "text": "…",
                                        "accept": [0, 2],
                                        "groupUuid": null}               → 并入草稿，返回新草稿
```

两个接口都需要问卷上的编辑权。`accept` 是预览里的 `index`；`groupUuid` 为空时新建一个名为
「导入的题目」的分组，指定时追加到该分组末尾。`expectedVersion` 与保存草稿是同一把乐观锁。

## 六、限制与后续

1. 只支持上面这一种写法；Word / Excel 粘贴过来的编号样式（如 `一、`、`（1）`）暂不识别，会记 `unrecognized_line`。
2. 选项属性（其他项、互斥项、分值）、题目属性（长度上限、日期范围）不能在文本里写，导入后再编辑。
3. 矩阵、双尺度等需要子题＋选项两维的题型不在本批；排序题只导入子题。
4. 预览不落库，因此"预览 → 确认"之间没有服务端的暂存；确认时原文要原样再传一次（同一份原文即同一份结果）。
