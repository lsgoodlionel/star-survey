## 2. 冻结范围与出版条件

冻结范围是产品化已有后端、关闭生产阻断并建立单机交付，不新增统计、AI、支付、预约、签署、投票、360、

## 3. 信息架构

### 3.1 一级工作区

| 一级工作区 | 用户问题 | 目标内容 | 导航条件 |
|---|---|---|---|
| 工作台 | 我现在该继续什么？ | 最近问卷、待审批、发布异常、快捷入口 | 保留现有 `/workspace`，只展示真实数据 |
| 问卷 | 如何创建、配置、预览和发布？ | 资源、模板、编辑、品牌、访问规则、发布与版本 | 问卷上下文可恢复，子页均为真实路由 |
| 投放 | 如何找到受众并触达？ | 联系人、部门、标签、名单、链接、二维码、任务、催答 | Wave 4 闭环前不进入正式一级导航 |
| 数据 | 回收了什么，如何交付？ | 答卷、摘要、字段、导出任务和下载 | Wave 3 闭环前不进入正式一级导航 |
| 管理 | 谁能用、系统如何运行？ | 成员、组织连接、套餐、引擎实例、平台模板 | 按租户管理与平台运维分权 |

当前正式路由只有 `/workspace` 与 `/surveys/:surveyId/{edit,import,preview,publish,versions/:version}`。
上表是 Wave 0-6 的目标 IA，不得把尚无页面的目标项写成当前路由。

### 3.2 一级导航规则

- 一级导航只放稳定工作区，不用禁用菜单或空页面预告未来能力。
- 入口可见性由服务端能力和业务权限决定，不从 JWT 角色名推测。
- 租户切换、重新认证和页面返回时保留合法的资源、问卷、筛选和任务上下文。
- 全局状态区展示当前租户、运行异常和待处理事项；问卷状态留在问卷上下文，不挤入全局导航。
- 小屏使用菜单或分组入口，但工作区名称、当前对象和主要动作必须可发现。

## 4. 问卷内工作流

目标顺序：

```text
编辑 | 导入 | 品牌 | 访问规则 | 真实预览 | 发布与版本 | 投放 | 答卷与导出
```

其中“快速预览”继续作为本地草稿 renderer，必须与“真实预览”明确区分。问卷头部持续显示问卷名称、草稿版本、
发布状态、未保存状态和面包屑；切换子页不丢失选中题目、筛选或正在处理的任务。

发布成功后的默认下一步是“真实预览”“获取答卷链接”“查看答卷”，而不是只停在版本号。发布失败时保留草稿和审批上下文，
显示漂移、人工复核、孤儿引擎问卷或依赖不可用的真实状态。

### 4.1 编辑器布局

- `>=1180px`：大纲、编辑区、属性检查器三栏。
- `820-1179px`：大纲 + 编辑区为主体，属性检查器按选中内容打开；此 Phase C 目标尚未交付。
- `<820px`：大纲、编辑、属性使用标签或抽屉切换，当前问卷和保存状态始终可见。
- 所有关键动作满足键盘、焦点、触摸目标和读屏替代路径；未知字段继续无损往返。

## 5. 工作区间用户流

### 5.1 作者主链

```text
工作台 -> 创建/进入问卷 -> 编辑或导入 -> 品牌/访问规则
       -> 快速预览 -> 隔离真实预览 -> 审批 -> 发布
       -> 链接/二维码 -> 正式作答 -> 答卷 -> 导出
```

任一节点失败都返回可恢复状态，不把用户送入 LimeSurvey 管理后台。作者可以跨工作区继续同一问卷，链接必须携带稳定问卷上下文。

### 5.2 运营与数据链

投放工作区从通讯录/名单进入问卷投放上下文；数据工作区可从全局任务列表或问卷内“答卷与导出”进入。
任务型页面统一显示任务状态、进度、失败原因、重试/取消和产物过期，不把后台作业表现成同步成功。

### 5.3 管理链

租户管理员只管理当前租户的成员、组织连接和模板；平台运维管理引擎实例、生产诊断和生命周期。
二者在信息架构上分组，在权限和审计上彻底分离。

## 6. 引擎边界

- Platform Service 是租户、权限、问卷定义、版本、审批、投放、答卷投影和任务状态的业务事实来源。
- Admin Web 只访问同源 `/v1`；不得直连发布网关、数据库或 LimeSurvey RemoteControl。
- Publish Gateway 是平台到引擎的受控适配层，持有引擎凭据但不代替平台做业务授权。
- LimeSurvey Runtime 承担隔离真实预览和正式作答；预览使用独立 SID/世代，预览答卷不进入正式数据链。
- LimeSurvey `/admin` 不进入业务导航。生产仅以 `/engine-admin/*` 暴露给受限平台运维身份。
- 资产、字典、品牌和策略在发布时固定到版本快照；作答页不能依赖任意回连平台才能正确运行。

## 7. 状态与可恢复性

每个工作区统一呈现 loading、empty、forbidden、temporarily unavailable、retryable failure 和 terminal failure。
`401` 保留允许恢复的本地上下文后重新认证；`409` 保护用户修改；`422` 定位到字段或步骤；`503` 显示依赖不可用。
页面、URL 和后台任务状态必须同源，刷新或跨页面后不能把失败任务显示为成功。

## 8. Wave 0-6 在蓝图中的落点

- Wave 0 建立基线和生产骨架，不新增正式业务导航。
- Wave 1 补齐发布后的真实预览、链接、二维码、答卷和导出入口。
- Wave 2 补齐模板、品牌和多语言配置。
- Wave 3 形成数据工作区。
- Wave 4 形成投放工作区。
- Wave 5 完成编辑器 Phase C 和首批高级题型配置。
- Wave 6 完成管理工作区和生产验收。

每个 Wave 只有在路线图准出条件满足后，才把对应目标 IA 视为已交付。
