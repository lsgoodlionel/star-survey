冻结范围：Wave 0-6 只产品化现有后端、关闭生产阻断、建立单机生产生命周期和首批高级题型可视化。

出版条件分两层：

1. 路线图出版：三份 canonical 文档、能力映射、README、P2 进度和追溯登记互相引用且数字一致。
2. 产品/Release 出版：对应 Wave 的需求、后端、前端、流程、生产、追溯六层证据齐全，准出条件全部通过，
   能力状态由 `capabilities.json` 合法提升并重新生成映射。文档叙述不能代替该状态转移。

## 3. 全局门禁

### 3.1 全局准入条件

- 上一 Wave 已有可运行版本和明确未通过项；不得以多个半成品并行替代顺序验收。
- 需求编号、角色、正常流、失败流和验收断言已经进入需求基线。
- 所需后端接口已存在，或最小契约补充属于冻结范围允许的三类变更。
- 安全、数据迁移、生产拓扑或外部凭据依赖已被显式识别。

### 3.2 全局准出条件

- 用户可从正式导航完成正常流，并在 401/403/404/409/422/503 场景得到可恢复结果。
- 自动化串起 Admin Web、Platform、Gateway、数据库和 LimeSurvey；需要作答的流程使用真实引擎。
- 同一流程在 Production Compose 通过，不依赖 `/dev/token`、演示账户、宿主机数据库端口或测试数据。
- 六层证据具有路径、定位符和结构化验证信息；生成器、追溯检查和相关测试全绿。
- README、进度、GitHub/Release 和外部项目记录同步，不将局部子断言写成整条需求 Accepted。

## 5. 依赖与发布顺序

首批实施顺序固定为：需求证据基线 -> 单机生产基座 -> 发布后闭环 -> 多架构 Release。合并顺序固定 A -> B -> C -> D。
Wave 2-6 各自单独编写实施计划，只在前一 Wave 形成可运行版本后开始。外部凭据可以并行准备，但不得用模拟成功替代真实验收。

候选版允许记录非阻断缺陷；稳定版还必须满足：所有必需测试和 Ubuntu/架构矩阵均未跳过，严重/高危安全问题为零，
安装、升级、回滚或恢复、卸载均有证据，Release 制品和需求/进度同步完整。
