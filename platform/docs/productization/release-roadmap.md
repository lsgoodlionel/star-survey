## 2. 冻结范围与出版条件

冻结范围：Wave 0-6 只产品化现有后端、关闭生产阻断、建立单机生产生命周期和首批高级题型可视化。
统计、AI、支付、预约、签署、投票、360、体验管理、Kubernetes、高可用、多节点数据库和跨区域灾备全部延后。

出版条件分两层：

1. 路线图出版：三份 canonical 文档、能力映射、README、P2 进度和追溯登记互相引用且数字一致。
2. 产品/Release 出版：对应 Wave 的需求、后端、前端、流程、生产、追溯六层证据齐全，准出条件全部通过，
   能力状态由 `capabilities.json` 合法提升并重新生成映射。文档叙述不能代替该状态转移。

## 3. 全局门禁

### 3.1 全局准入条件

- 上一 Wave 已有可运行版本和明确未通过项；不得以多个半成品并行替代顺序验收。
- 需求编号、角色、正常流、失败流和验收断言已经进入需求基线。
- 所需后端接口已存在，或最小契约补充属于冻结范围允许的三类变更。
- 安全、数据迁移、生产拓扑或外部凭据依赖已被显式识别。

### 3.2 全局准出条件

- 用户可从正式导航完成正常流，并在 401/403/404/409/422/503 场景得到可恢复结果。
- 自动化串起 Admin Web、Platform、Gateway、数据库和 LimeSurvey；需要作答的流程使用真实引擎。
- 同一流程在 Production Compose 通过，不依赖 `/dev/token`、演示账户、宿主机数据库端口或测试数据。
- 六层证据具有路径、定位符和结构化验证信息；生成器、追溯检查和相关测试全绿。
- README、进度、GitHub/Release 和外部项目记录同步，不将局部子断言写成整条需求 Accepted。

## 4. Wave 0-6

### Wave 0：需求基线与生产骨架

依赖：上位设计、总计划、全量核查报告和 305 条需求矩阵。

准入条件：当前能力状态已经由 schema 和强类型证据校验；生产阻断清单已排序；Production Compose 与生命周期工具边界锁定。

目标交付：三份 canonical 文档；机器能力映射；Production Compose、反向代理、持久卷、环境模板、健康检查；
`surveyctl` 骨架；多架构与 Release 流水线骨架。

准出条件：无开发入口、无测试令牌、无宿主机数据库端口启动并通过健康检查；文档链一致；此阶段不因骨架存在提升业务能力为 accepted。

### Wave 1：发布后闭环

依赖：Wave 0 生产基座；审批发布、投放链接、答卷查询和导出已有后端契约；隔离预览最小契约明确。

准入条件：正式发布与隔离预览的 SID/世代、数据投影和错误语义已经分离；发布状态可真实读取。

目标交付：真实运行状态、隔离真实预览、公开地址、二维码、答卷数量、回收状态以及数据/导出入口。

准出条件：作者从发布页完成隔离预览、获取正式链接、真实作答、查看答卷并生成导出；预览答卷不进入正式数据；
同一旅程在 Production Compose 和真实浏览器中通过。

### Wave 2：模板与品牌闭环

依赖：Wave 1 真实预览和发布版本固定能力；模板、品牌、多语言和资产契约可用。

准入条件：平台模板与租户模板权限、审批和复制边界明确；品牌资产版本可固定并在预览中读取。

目标交付：模板浏览/筛选/详情/复制/审批；主色、标题、页脚、Logo/素材和多语言配置。

准出条件：从批准模板创建问卷，配置品牌，隔离真实预览，发布并完成品牌化作答；模板不携带原项目敏感数据。

### Wave 3：数据产品化

依赖：Wave 1 产生可追溯正式答卷；查询、字段、摘要和导出任务后端可用。

准入条件：跨版本游标、权限、脱敏、导出快照和下载再授权语义锁定；真实支持格式清单已核对。

目标交付：答卷列表、复合筛选、字段选择、摘要；导出创建、进度、取消、重试、下载和过期状态。

准出条件：跨版本查询无漏重；无明细权限角色只能看摘要；下载前再次授权；失败/过期任务可恢复且不生成假产物。

### Wave 4：通讯录与投放

依赖：Wave 1 正式链接；Wave 3 可核对完成状态；联系人、部门、标签、名单和投放任务后端可用。

准入条件：去重键、数据范围、通道可用性、回执验签、退订和催答上限已定义；外部供应商依赖可识别。

目标交付：通讯录、名单、导入任务、受众选择、投放链接、二维码、批量任务、逐收件人回执、催答和退订。

准出条件：从名单创建投放并查看真实状态；崩溃恢复不重发；完成者不再收到催答；未配置通道显示不可用，不使用成功假数据。

### Wave 5：编辑器 Phase C 与高级题型

依赖：Wave 2 品牌/资产；Wave 1 真实预览；题型插件、主题和服务端校验已存在。

准入条件：`820-1179px` 目标布局、未知字段无损契约、键盘/读屏/触摸路径和首批题型 schema 已确认。

目标交付：中间断点大纲 + 编辑区 + 属性检查器；中文题型面板、保存时间、版本/冲突状态；折叠栏目、多级下拉、轮播图配置。

准出条件：三种题型完成配置、保存、隔离真实预览、发布、作答和回读；未知字段无损；专项可访问性和多视口浏览器验收通过。

### Wave 6：运营后台与生产验收

依赖：Wave 0 生命周期基座以及 Wave 1-5 的最小业务旅程。

准入条件：租户/平台管理权限分离；生产安全阻断关闭计划、容量基线、备份 schema 和升级兼容矩阵明确。

目标交付：租户、套餐、成员、组织连接、引擎实例和平台模板管理；安全修复；安装、升级、回滚/恢复、备份、故障排查和卸载文档。

准出条件：干净 Ubuntu 22.04/24.04 的 AMD64/ARM64 主机安装同一候选版，完成最小业务旅程，升级、核对数据，
按 manifest 回滚或恢复并安全卸载；Release 含固定 digest、checksum、签名/证明、SBOM、manifest 和升级说明。

## 5. 依赖与发布顺序

首批实施顺序固定为：需求证据基线 -> 单机生产基座 -> 发布后闭环 -> 多架构 Release。合并顺序固定 A -> B -> C -> D。
Wave 2-6 各自单独编写实施计划，只在前一 Wave 形成可运行版本后开始。外部凭据可以并行准备，但不得用模拟成功替代真实验收。

候选版允许记录非阻断缺陷；稳定版还必须满足：所有必需测试和 Ubuntu/架构矩阵均未跳过，严重/高危安全问题为零，
安装、升级、回滚或恢复、卸载均有证据，Release 制品和需求/进度同步完整。

## 6. 延后项

- 未完成后端业务包：统计、AI、支付、预约、签署、投票、360、体验管理及其前端。
- 分布式生产：Kubernetes、高可用、多副本状态协调、多节点数据库、跨区域灾备。
- 需要业务或供应商输入的 15 条外部项，只有真实凭据、许可或法务结论到位后才能进入对应 Wave。
- PDF 中文字体、附件大文件通道、行政区划数据许可等现有明确阻断，继续保留为有依据的待办。
- 任何未进入六层证据的 Controller、测试、页面草图、流水线骨架或文档，不进入 Release 完成清单。
