## 2. 冻结范围与出版条件

### 2.1 冻结范围

本阶段冻结新的后端业务包。只允许三类后端变更：前端接入现有能力所必需的查询、聚合或契约补充；
核查报告确认的安全、一致性和生产阻断修复；Production Compose、生命周期工具和 Release 所必需的运行能力。
统计、AI、支付、预约、签署、投票、360、体验管理等未完成业务包不进入 Wave 0-6。

### 2.2 出版条件

本文可以作为需求基线发布，但任何“产品完成”或稳定版声明必须同时具备需求、后端、前端、真实流程、
生产和追溯六层强类型证据。页面存在、Controller 存在、单项测试通过或本文写有验收断言，都不能单独改变
能力状态。Wave 0 至 Wave 6 的准入和准出以 `platform/docs/productization/release-roadmap.md` 为准。

## 3. 角色

| 角色 | 主要目标 | 权限边界 |
|---|---|---|
| 作者 | 创建、编辑、预览、提交审批、发布并继续投放 | 只操作获授权资源；不能自行绕过审批或生产闸门 |
| 审核者 | 核对指定草稿版本并批准、驳回或要求修改 | 批准只绑定提交时版本；改稿后原批准失效 |
| 数据人员 | 查看答卷、字段和摘要，创建并下载导出 | 明细、敏感字段和下载均需独立授权 |
| 投放运营 | 管理联系人、名单、链接、任务、回执和催答 | 不能越租户；通道不可用时不得伪造成功 |
| 租户管理员 | 管理成员、组织连接、模板和租户级配置 | 不拥有平台级租户或引擎实例运营权限 |
| 平台运维 | 管理生产安装、引擎实例、备份、升级和诊断 | 不通过业务导航进入；诊断不得暴露凭据 |
| 作答者 | 通过公开或受限链接完成真实作答 | 只能访问当前发布版本和策略允许的数据 |

## 4. 通用交互与错误契约

所有用户页面必须有加载、空状态、无权限、暂时不可用、可重试失败和不可重试失败。业务错误统一遵循：

- `401`：清除会话，保留允许恢复的同租户本地编辑上下文，并引导重新认证。
- `403`：说明缺少的业务权限，不泄露不可见资源的内容或存在性。
- `404`：统一表达资源不存在或不可见。
- `409`：保留用户修改，显示版本冲突和恢复入口，不以服务端内容静默覆盖。
- `422`：在字段或任务步骤旁显示可纠正的校验问题。
- `503`：显示依赖暂时不可用和安全重试入口，不生成假链接、假回执或假导出。

## 5. 用户旅程需求

### 5.1 工作台与问卷创建

需求关联：`R01-01`、`R19-04`。主要角色：作者。

前置条件：用户完成可信登录；平台返回租户和资源能力；项目、文件夹或问卷操作由服务端授权。

正常流：作者进入工作台，恢复最近位置，搜索或筛选资源，进入项目/文件夹，创建空白中文问卷或从已批准模板创建，
随后进入问卷工作流。

失败流：租户不可用、资源不可见、名称冲突、创建校验失败或服务暂时不可用时，页面保留当前位置和筛选条件，
显示可执行的恢复动作；不得用 Token 角色猜测能力。

验收断言：

- 服务端资源能力决定可见操作，跨租户资源始终不可见。
- 页面切换或重新认证后恢复最近工作上下文，不把未保存内容带到另一租户或问卷。
- 创建成功后 URL、面包屑、资源树和页头指向同一资源。

### 5.2 编辑与导入

需求关联：`R01-02`、`R01-04`、`R01-05`、`R01-08`。主要角色：作者。

前置条件：问卷草稿可读且用户有编辑权限；客户端持有当前 `draftVersion`。

正常流：作者编辑基础题型、稳定排序并保存；未知字段无损往返。批量导入先预览，保留原始行号和错误，
作者选择可导入项及目标题组后确认，成功后刷新当前草稿版本。

失败流：`409` 时保留本地改动并提供冲突处理；导入坏行不阻断其他合法行；网络失败后不得把本地草稿标为已保存；
只读高级题型不得被序列化过程破坏。

验收断言：

- 保存请求携带当前版本，响应版本成为下一次保存基线。
- 题组、题目 UUID 在编辑和排序后保持稳定，未知字段字节语义无损。
- 导入预览不写库；只有已勾选且通过校验的 ordinal 才进入指定题组。
- Wave 5 完成前，高级题型只读保真不等于可视化配置完成。

### 5.3 预览、审批与发布

需求关联：`R01-07`、`R01-09`。主要角色：作者、审核者。

前置条件：草稿可读取；真实预览使用隔离引擎 SID/世代；发布绑定明确版本和审批状态。

正常流：作者可先使用明确标识的快速预览，再创建隔离真实预览；提交审批后，审核者针对固定草稿版本处理；
批准后作者发布该版本，并从发布结果继续获取真实预览、答卷链接、二维码、答卷和导出入口。

失败流：预览创建失败不得回退为正式答卷链接；提交后改稿使批准失效；发布出现 `202`、漂移、孤儿问卷或引擎故障时，
显示真实状态和安全恢复动作，不宣称发布成功。

验收断言：

- 隔离预览答卷不进入正式投影、统计和导出。
- 审批只允许发布被批准版本，任何后续改稿都必须重新审批。
- 发布结果能追溯平台版本、引擎 SID/世代和公开地址；失败不留下部分成功状态。

### 5.4 投放、作答、答卷与导出

需求关联：`R05-01`、`R05-04` 至 `R05-09`、`R06-01` 至 `R06-07`、`R19-02`。主要角色：投放运营、作答者、数据人员。

前置条件：问卷已发布；链接和二维码由平台生成；作答策略已固定；数据人员拥有相应摘要、明细或导出权限。

正常流：运营创建公开或定向链接并选择名单，启动投放任务，查看逐收件人回执和催答状态；作答者完成真实作答；
数据人员跨版本查询答卷和摘要，创建导出任务，查看进度并在下载时再次授权。

失败流：供应商未配置时明确显示通道不可用；任务崩溃恢复不得重发；撤销、过期和未知短链返回不可区分的失败；
网关不可达、导出失败或文件过期时提供重试/重建入口，不返回空文件冒充成功。

验收断言：

- 同一收件人不会因恢复或重复回执被重复发送或重复计数，完成者不再收到催答。
- 无明细权限的角色只能看到允许的摘要；跨租户、跨问卷和敏感字段访问被拒绝。
- 导出固定快照，支持取消和失败重试；下载前再次授权，只显示真实支持的格式。
- 正式作答可从发布版本追溯到答卷、导出任务和下载制品。

### 5.5 模板、品牌、通讯录与管理

需求关联：`R01-03`、`R01-06`、`R18-01` 至 `R18-06`、`R19-01`、`R19-03`、`R19-05`、`R19-06`、`R19-10`、
`R20-01` 至 `R20-03`、`R22-01`、`R22-11`、`R22-12`。主要角色：作者、投放运营、租户管理员、平台运维。

前置条件：模板版本已批准；品牌资产可访问；组织和联系人数据属于当前租户；管理动作具有明确平台或租户级权限。

正常流：作者从模板创建并配置品牌、多语言和资产，在隔离真实预览中核对后发布；运营导入联系人、处理坏行和去重，
建立部门、标签和名单；管理员配置成员、组织连接、套餐、引擎实例和平台模板。

失败流：未批准模板不可见；资产版本丢失时阻止发布；联系人坏行可定位且不终止整批；离职或失权立即收回访问；
平台级动作不得出现在租户管理员界面。

验收断言：

- 模板不携带原问卷参与者、访问密码或管理员联系人，品牌配置随发布版本固定。
- 联系人去重键和数据范围由租户配置及服务端执行，跨租户标签/名单不可引用。
- 生产管理动作留下可追溯审计；业务用户不会被引导到 LimeSurvey `/admin`。

### 5.6 单机生产与版本生命周期

需求关联：`R20-11`、`R23-08` 至 `R23-12`。主要角色：平台运维。

前置条件：受支持 Ubuntu 22.04/24.04、AMD64/ARM64；目标 Release 元数据、签名、校验和和兼容范围可验证。

正常流：运维预检主机，安装固定 digest 制品，运行最小业务探针；升级前备份并校验，完成迁移和探针后切换当前版本；
可按 manifest 声明执行回滚或备份恢复；普通卸载保留数据。

失败流：架构、端口、磁盘、DNS、时间、签名、校验和、迁移或探针任一失败即停止；不可逆迁移只允许 restore-only；
诊断包必须脱敏，禁止把开发 Token、密码、Cookie、私钥或完整环境文件写入输出。

验收断言：

- 公网仅由反向代理监听 80/443，数据库、平台、网关和引擎不发布宿主机端口。
- 全新安装、幂等重跑、升级、回滚或恢复、备份恢复和卸载均有对应生产证据。
- 同一 Release 在两种 Ubuntu LTS 和两种架构上完成原生运行验证；QEMU 构建成功不代替运行验收。
- Release 可追溯需求、提交、测试、镜像 digest、SBOM、升级说明和发布证明。

## 6. 状态维护规则

Wave 0-6 只安排交付顺序，不直接改变需求或能力状态。实现完成后，先将六层证据写入机器真源并通过生成器和追溯检查，
再同步 README、进度、GitHub 和外部项目记录。没有六层证据时，文档只能描述“计划”“部分完成”或“未开始”，
不得使用“已验收”“可发布稳定版”等措辞。
