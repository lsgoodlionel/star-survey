## 闸门结论

`platform/deploy/test/run-p1-e2e.sh` 启动三个真实进程（平台业务服务、发布网关、引擎测试栈），
在 `TEST_DB=mysql` 与 `TEST_DB=pgsql` 上均通过，断言链路：

运营开租户 → 发布套餐 → 开通并初始化所有者 → 激活租户 → 登记引擎实例并签发实例事件密钥
→ 所有者建问卷、存草稿、发布 → 平台记录版本 1 与题目绑定、登记公开路由（正反查）
→ 引擎中问卷已激活且只建了一份 → 经 HTTP 真实作答 → 引擎事件经签名中继进入平台投影（`engine_completed`）
→ 重复发布 409 `already_published`，网关未被再次调用。

## 过程中修掉的真实缺陷

- 引擎事件共用一把密钥，一个实例可冒充其他实例 → 改为每实例派生密钥，批内事件必须属于认证实例；
- 网关读超时抛错类型不对，导致跳过回滚、引擎残留半发布问卷 → 统一转为 `RpcError` 并回滚；
- owner 为超级用户时绕过 RLS → 改为非超级用户；
- 框架层错误转发 `/error` 被掩盖为 401 → 放行 ERROR 分派；
- 测试用席位额度对所有租户一律 50，掩盖了权限与额度未联动 → 有订阅的租户走真实额度。

## 已知限制（转入 P2 待办）

1. **没有项目 / 目录的创建 API**：端到端脚本用 psql 在租户 RLS 范围内插入项目；谁能建项目待产品确定。
2. **没有审批流程**：需审批的子账号发布只得到 403 `approval_required`，无可提交的申请。
3. **已发布问卷不能再发布**（409）：网关尚不支持改版发布（ADR 0009 限制 2）。
4. **"待核对"没有后台核对任务**：只在再次调用发布时落定。
5. **网关只能单副本**：并发锁在进程内。
6. 租户有多个活动引擎实例时取最早登记的一个；问卷表对资源树与引擎实例没有跨模块外键。
7. 端到端脚本复用固定容器名（`COMPOSE_PROJECT_NAME=survey`），不能与其他引擎测试同时跑；引擎管理员口令会出现在容器内安装命令行上（随机、仅测试）。
