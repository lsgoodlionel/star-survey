短窗口比最近 24 小时均速低 83.5%，比历史高强度均速低 96.4%；raw token 的 cache 占比约 78.3%。这证明当前空转和重复上下文显著减少，但 2 小时 42 分钟样本过短，不能直接宣称后续每个产品 Milestone 都会保持 96.4% 降幅。

既有优化计划对全部剩余开发的预算仍采用 32M-58M active Token；旧流程为 56M-98M，预计节省 24M-40M。按最近 24 小时的 3.45M active/day，模型密集开发约需 9-17 天；若长期只有当前低强度约 0.57M/day，则会拉长到 56-102 天。合理排期应维持 1.1M-3.2M active/day 的专注开发强度，同时把测试执行留在本地或 GitHub，只将脱敏失败摘要交给模型。

## 6. Token 成本控制要求

- 新 Agent 只加载 Context Capsule、任务增量和一个有界失败摘要；不重复读取全量计划、报告、日志或 Obsidian Vault。
- 成功测试只返回结构化计数；原始日志保留本地，失败时最多暴露一个根因和三个相关错误。
- 相同 EvidenceKey 的 Gate 复用可信证据或共享租约；HEAD、发布和生产最终验收不得跨提交复用。
- 本地与 GitHub 执行测试本身不消耗模型 Token；只有诊断和修复需要模型上下文。
- 每完成 Wave 2 和 Wave 3 各一个代表性 Milestone 后重新测量项目归属明确的 active Token、Gate 执行/复用次数和 Agent 启动量，再修正 32M-58M 预算。
