# Wave 2 模板与品牌闭环设计

状态：已确认（2026-10-11）
设计方向：已于 2026-10-11 确认
目标分支：`feat/admin-product-alignment`

## 1. 背景与当前事实

Wave 1 已建立管理端问卷工作台、真实预览、发布、作答入口和版本链路。Wave 2 的目标不是重新实现后端模板、资产或品牌编译能力，而是把已经存在的后端能力前端化，并补齐为可独立验收的产品闭环。

现有后端事实：

- 租户模板接口位于 `/v1/survey-templates`，已经支持列表、详情、版本定义、从问卷创建/新增版本、提交审核、审核通过/驳回、下架和复制为独立问卷草稿。
- 平台模板接口位于 `/v1/platform/survey-templates`，已经支持创建、列表、详情、新增版本、发布和下架，并由 `platform_operator` 权限保护。
- 作者资产接口位于 `/v1/assets`，已经支持上传、版本、列表、内容读取、归档和删除；发布时按资产当前版本生成不可变引用。
- 问卷草稿通过 `PUT /v1/surveys/{id}/draft` 和 `expectedVersion` 乐观锁保存。
- `branding` 与 `translations` 已是问卷定义的顶层契约；发布网关负责校验并编译到 `zh-business` 主题。
- 管理端当前没有模板入口、品牌页或对应 API client，能力矩阵中的 `templates-branding` 仍是后端部分完成、前端未开始。

## 2. 目标与非目标

### 2.1 本 Wave 目标

1. 用户可浏览平台和租户模板，按范围和状态筛选，查看模板详情并复制为独立问卷。
2. 有权限的用户可从现有问卷创建租户模板、添加版本、提交审核并完成审核流转。
3. 平台运营角色可在同一产品入口管理平台模板，不暴露给普通租户用户。
4. 用户可在问卷内配置主色、标题、页脚、Logo、favicon 和多语言文案，并通过现有草稿版本机制安全保存。
5. 品牌配置可进入真实预览、发布快照和作答页，已发布版本不受后续草稿或资产更新影响。
6. 模板复制不携带答卷、联系人、密码、管理员联系方式或平台生成字段。

### 2.2 本 Wave 非目标

- 不开放租户自定义 CSS、JavaScript、HTML 或外部资源 URL。
- 不新增模板交易、模板市场计费、公开匿名模板分享或跨租户直接复制。
- 不在本 Wave 重做完整翻译工作台；只提供当前契约覆盖的语言和文案配置。
- 不提前实现 Wave 3 数据产品化、Wave 4 通讯录投放或剩余后端领域。
- 不用模拟数据代替真实预览、发布和作答验收。

## 3. 角色与权限

| 操作 | 普通作者 | 租户模板审核者 | 平台运营者 |
|---|---:|---:|---:|
| 浏览已发布平台模板 | 是 | 是 | 是 |
| 浏览本租户模板 | 是 | 是 | 按平台接口 |
| 复制模板为问卷 | 是 | 是 | 否 |
| 从问卷创建或更新租户模板 | 是 | 是 | 否 |
| 提交租户模板审核 | 是 | 是 | 否 |
| 审核、驳回、下架租户模板 | 否 | 是 | 否 |
| 管理平台模板 | 否 | 否 | 是 |
| 编辑问卷品牌 | 具备问卷编辑权限时 | 具备问卷编辑权限时 | 否 |

前端只负责隐藏和禁用不可用操作，后端仍是权限判定的唯一权威。平台角色和租户角色不得通过客户端参数相互替代。

## 4. 信息架构与路由

### 4.1 全局模板中心

- 新增一级导航“模板中心”，路由 `/templates`。
- 默认展示可用模板，范围筛选为“全部 / 平台 / 本租户”。
- 状态筛选为“可使用 / 草稿 / 审核中 / 已驳回 / 已下架”，只显示调用者有权看到的值。
- 列表采用适合后台高频浏览的紧凑表格或列表，不使用营销式卡片墙。
- 模板详情使用 `/templates/:templateId`，展示来源、状态、当前版本、更新时间、说明和安全复制摘要。
- 审核队列作为 `/templates?view=review` 的同页视图，不再创建第二套导航。
- 平台运营操作在相同信息架构内按角色显示，但调用 `/v1/platform/survey-templates`。

### 4.2 问卷品牌页

- 在 `SurveyShell` 增加“品牌与语言”页签，路由 `/surveys/:surveyId/branding`。
- 页面分为基础品牌、品牌资产和多语言三个连续区域，不嵌套卡片。
- 页面沿用 SurveyShell 的未保存离开拦截、页面就绪状态、最近工作和草稿版本提示。
- 保存成功后更新 SurveyShell 中的 `draftVersion`，使预览、审批和发布读取同一版本。

### 4.3 创建入口

- Workspace 的“新建问卷”保留空白问卷入口，并增加“从模板创建”。
- 问卷内提供“保存为模板”，进入命名和说明对话框后调用现有租户模板接口。
- 模板复制成功后直接进入新问卷编辑页，保留返回模板详情的来源上下文。

## 5. 前端 API 与数据模型

新增 `shared/api/templates.ts`、`shared/api/assets.ts` 和 `shared/api/branding.ts`，所有响应先用 Zod 校验再进入页面状态。

模板 client 直接覆盖现有接口，不为相同动作新增后端别名：

- `GET /v1/survey-templates?scope=...`
- `GET /v1/survey-templates/pending`
- `GET /v1/survey-templates/{templateId}`
- `GET /v1/survey-templates/{templateId}/versions/{versionNo}`
- `POST /v1/survey-templates`
- `POST /v1/survey-templates/{templateId}/versions`
- `POST /v1/survey-templates/{templateId}/submit|approve|reject|unpublish`
- `POST /v1/survey-templates/{templateId}/copies`
- 对应的 `/v1/platform/survey-templates` 运营接口。

品牌页读取问卷 overview 和 draft，保存时继续调用现有 `PUT /v1/surveys/{id}/draft`：

1. 保留草稿中未知且不由本页管理的所有顶层字段。
2. 只替换 `theme`、`branding`、`additionalLanguages` 和 `translations`。
3. 请求携带读取时的 `expectedVersion`。
4. 发生版本冲突时不自动覆盖，提示用户重新载入；本 Wave 不做字段级自动合并。
5. 保存前执行与后端契约一致的客户端校验，但服务器 422 仍以字段级中文错误展示。

本 Wave 不新增专用 branding 后端端点。若实现中证明整份草稿保存无法可靠保留编辑器并发状态，必须暂停并形成 ADR，不得临时绕过乐观锁。

## 6. 品牌资产映射

品牌 Logo 和 favicon 复用 `/v1/assets` 作者资产库：

1. 页面只展示 `origin=AUTHOR`、状态为 ACTIVE 且 MIME 类型为允许图片类型的资产。
2. 用户可选择已有资产或上传新资产；上传返回的 `assetId` 是作者侧稳定标识。
3. 草稿定义中的品牌引用使用 `logoAsset: {"assetId":"<uuid>"}` 与 `faviconAsset: {"assetId":"<uuid>"}`；由预览/发布链路固定实际版本并物化为主题文件名。
4. 禁止把客户端原始文件名、任意 URL 或手写 `assetVersion` 当成可信输入。
5. 已发布版本引用固定资产版本；之后新增资产版本只影响未来保存并发布的新版本。

现有 `survey-branding-v1` 仅描述编译后的 `logoFile` 和 `faviconFile`。实现前需要增加一份向后兼容的作者态映射契约，并由 `SurveyAssetLinks` 与发布网关共同测试。平台物化后可以携带受信 `url` 与 `assetVersion` 供网关取件，但作者草稿不得写入这两个字段。旧定义中的合法文件名继续可读，新管理端新写入必须使用平台资产引用，同一图片槽位不允许两套来源同时存在。

## 7. 模板生命周期

租户模板状态机沿用后端现状：

1. 从问卷草稿创建模板，状态为草稿。
2. 作者可从新的问卷草稿添加模板版本。
3. 提交后进入审核中，提交版本固定。
4. 审核者可批准或带原因驳回。
5. 只有可使用版本可复制为问卷。
6. 下架只阻止新复制，不影响已经复制出的独立问卷。

平台模板由平台运营者直接创建和发布。前端不得把租户审核动作映射为平台发布动作。

复制操作必须创建独立问卷草稿：后续修改模板不改变已复制问卷，后续修改问卷也不反写模板。详情页明确显示来源和版本，但不建立可变继承关系。

## 8. 品牌与多语言规则

- 品牌出现时 `theme` 固定为 `zh-business`。
- 主色只接受 `#rgb` 或 `#rrggbb`。
- 标题、页脚和替代文本按纯文本保存和渲染。
- `customCss`、`customJs`、`headHtml`、`footerHtml` 和未知品牌键均拒绝。
- 语言列表必须包含一个基础语言；译文键只能来自 `additionalLanguages`。
- 翻译对象引用的 group、question、subquestion 和 answer 必须真实存在。
- 未翻译内容按基础语言回退，不生成空白题目。
- 管理端展示后端问题代码对应的中文解释，同时保留 trace 信息用于排障，不向用户显示 Java 异常文本。

## 9. 状态、错误与恢复

所有页面必须具备加载、空数据、无权限、网络失败、校验失败、版本冲突和操作进行中状态。

- 模板复制采用提交中锁定和幂等 UI，成功前不得重复发起。
- 审核动作完成后同时失效列表、详情和审核队列缓存。
- 资产上传显示真实进度或明确的不确定状态；失败后可重试，不伪造成功缩略图。
- 保存品牌失败时保留本地输入；版本冲突要求用户重新加载后再保存。
- 预览或发布失败时保留现有 Wave 1 诊断入口，并展示与品牌/资产相关的 422 或 503 原因。

## 10. 安全与隔离

- 租户 ID、操作者 ID 和权限都来自令牌，不从 URL 查询参数或请求体信任。
- 模板复制前后均验证租户隔离；跨租户资源对普通用户表现为不存在。
- 模板清洗继续由 `TemplateDefinitions` 负责，前端不得自行声称已经移除敏感数据。
- 作答页不得因品牌配置连接第三方来源；E2E 扫描 HTML、CSS 中的绝对 URL。
- 资产响应保持 `nosniff`、沙箱 CSP 和受控内容类型。
- Logo 必须有非空替代文本；纯装饰图只能显式标记为空替代文本。

## 11. 响应式与无障碍

- 桌面端模板列表支持快速筛选和键盘操作；窄屏转换为标签化行布局，操作菜单不横向溢出。
- 颜色输入同时提供原生色板和文本值，不能只依赖颜色表达状态。
- 上传、选择、移除资产都使用图标加可访问名称；不使用仅靠 hover 才能发现的操作。
- 表单错误与字段通过 `aria-describedby` 关联，保存结果使用非打断式 live region。
- 焦点顺序、对话框焦点圈定和 Escape 关闭行为进入组件测试与 E2E。

## 12. 验收链路

必须以真实前后端和真实引擎完成以下纵向流程：

1. 创建一份包含题目、品牌和至少一种附加语言的问卷草稿。
2. 上传 Logo，保存品牌，刷新页面后配置保持一致。
3. 真实预览中显示主色、Logo、标题、页脚和语言切换，且无第三方请求。
4. 将问卷保存为租户模板，提交审核并批准。
5. 另一名有权限用户从模板复制出独立问卷，源敏感数据不存在。
6. 修改复制后的问卷，模板定义不变化。
7. 发布复制问卷并完成一次真实作答。
8. 上传 Logo 新版本并再次发布，旧发布版本继续使用旧资产版本。
9. 平台运营者创建并发布平台模板，普通租户可浏览和复制，但不可管理。

## 13. 测试与质量门禁

- Java：模板状态机、权限、清洗、作者态品牌资产映射、发布版本固定和跨租户隔离测试。
- TypeScript：API schema、筛选、权限态、错误态、乐观锁、未保存离开和缓存失效测试。
- Playwright：模板复制、审核、品牌保存、真实预览、发布、作答、资产版本固定、窄屏和键盘流程。
- Docker：管理端、业务服务、发布网关和 LimeSurvey 的单机 Compose 联调。
- 文档：更新需求矩阵、能力矩阵、路线图、README 和交付 manifest，只记录有验证证据的完成项。

Wave 2 开工前必须先修复当前 GitHub `pull_request` 临时 merge commit 与交付证据绑定 branch HEAD 的治理门禁冲突。门禁失败时不得把 Wave 2 标为完成。

## 14. Agent 调度规则

本阶段不锁定单一模型。每次创建实现、审查或验证 Agent 时，调度器应根据任务复杂度、代码风险和当前运行时能力清单选择合适模型，并在运行记录中保存实际使用的模型与 reasoning effort。

- 机械性、边界清晰的任务优先使用快速模型。
- 跨模块集成、并发、权限、资产发布和生产验收任务使用具备足够上下文能力的模型。
- 安全、全分支和发布前审查不得低于对应实现任务的判断能力。
- 模型不可用、配额不足或运行时能力发生变化时暂停当前任务，不得静默替换为未记录的模型。

## 15. 交付顺序

1. 修复 CI 治理门禁的 PR merge commit 绑定问题。
2. 完成模板 API client、路由、列表、详情和复制闭环。
3. 完成租户模板创建、版本和审核闭环。
4. 完成品牌页、草稿保存和冲突恢复。
5. 完成品牌资产作者态契约和发布固定。
6. 完成多语言配置、真实预览、发布和作答闭环。
7. 完成平台模板运营入口、权限和全链路验收。
8. 同步代码、仓库文档、GitHub 和 Obsidian 交付证据。

只有上述验收链路全部通过，能力矩阵中的 `templates-branding` 才能从“后端部分完成/前端未开始”提升为已交付。
