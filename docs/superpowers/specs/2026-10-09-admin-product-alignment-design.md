# 管理端产品对齐与引擎入口治理设计

日期：2026-10-09

状态：待用户书面复核

目标阶段：P2 通用问卷与本土入口

依据：`01-开发设计蓝图.md`、`02-全量需求追踪矩阵.md`、`03-实施与验收计划.md`、`04-开发方案总蓝图（仓库校准版）.md`、`08-需求进度与方案修订（仓库实证）.md`、`docs/audits/2026-10-09-product-alignment/README.md`

## 1. 问题与决策

当前管理端已经打通创建、基础编辑、导入、审批发布和版本查看，但真实界面暴露出四个产品级问题：

1. 工作区把全局导航与资源树混在同一层，资源又按随机 UUID 排序；自动化测试数据持续累积，登录后无法按业务规律扫描。
2. 编辑、导入、预览、发布和版本是平级页面，没有统一问卷上下文；离开编辑器后容易丢失当前位置。
3. LimeSurvey 原生后台仍公开可达，业务用户容易误把引擎运维台当成本土化产品；原生后台没有品牌改造，因此看起来与上游一致。
4. 模板、品牌、题型主题、访问策略等大量后端能力没有管理端入口，开发成果无法形成用户可见闭环。

本设计采用以下产品边界：

- **平台管理端是业务用户唯一入口。** 作者、审核者和租户管理员只使用 React 管理端。
- **LimeSurvey `/admin` 是引擎运维控制台。** 不承载业务产品体验，不进行高成本全量换肤；通过网络、角色和文案边界限制给平台运维人员使用。
- **LimeSurvey 作答运行时继续保留。** 平台通过真实运行时预览展示 `zh-business`、题型主题和运行策略。
- **后端机制必须经平台页面和真实浏览器流程才能记为产品交付。** 单有接口、主题文件或单测不视为用户可见。

## 2. 目标与非目标

### 2.1 本轮目标

1. 建立稳定的四层信息架构：全局、资源、问卷工作流、编辑内部。
2. 将资源工作区从“无限树”改成可搜索、可过滤、可排序、可恢复上下文的工作界面。
3. 隔离 E2E 和人工演示数据，提供固定、可读、能体现开发成果的演示内容。
4. 修复平板宽度编辑器溢出，统一桌面、平板、移动布局规则。
5. 明确本地与生产 SSL 策略，消除本地无意义提醒且不弱化生产 TLS。
6. 为真实 LimeSurvey 运行时预览、模板库、品牌配置和高级题型页面建立可扩展入口。

### 2.2 非目标

- 不把 LimeSurvey Yii 后台重写成第二套业务管理端。
- 不在本轮一次性完成 47 类题型配置、全部逻辑 DSL、考试和运营后台。
- 不增加破坏性资源删除；资源治理首选可恢复的归档。
- 不把本地 HTTP 环境伪装为已启用 TLS。
- 不改变现有租户隔离、权限裁决、草稿乐观锁和发布状态机。

### 2.3 蓝图与需求映射

| 本设计交付 | 蓝图/追踪条目 | 对齐结果 |
|---|---|---|
| SurveyShell、编辑上下文与基础题型中文化 | R01-04 | 把已存在的基础编辑能力纳入连续、可恢复的产品流程 |
| 品牌配置入口与真实运行时展示 | R01-06、R19-06、R19-10 | 从“主题与契约存在”推进到可配置、可预览、可验收 |
| 快速预览与真实预览分层、发布与版本上下文 | R01-07 | 保留快速反馈，同时补齐真实引擎验收证据 |
| 稳定资源工作区、模板和待审批入口 | P2 通用问卷与本土入口 | 让后端能力在统一平台入口形成用户可见闭环 |

需求追踪文档中的完成状态必须按“代码存在、自动化通过、用户可见”分别记录；只有三项证据均满足时，才把本设计对应能力标为产品完成。

## 3. 信息架构

### 3.1 四层结构

```text
全局层
  工作台 | 问卷 | 模板 | 待审批 | 账号

资源层
  项目 > 文件夹 > 问卷

问卷工作流层
  编辑 | 导入 | 真实预览 | 发布与版本

编辑内部层
  题组 > 题目 > 当前对象属性
```

同一位置不再承担两种导航语义：工作区左侧只管理资源；编辑器左侧只管理当前问卷大纲。

### 3.2 全局应用框架

`AppShell` 提供：

- 产品名与工作台主页链接。
- 一级导航：工作台、问卷、模板、待审批。未交付页面可在路由就绪前不显示，不放禁用占位入口。
- 当前组织/用户菜单；业务界面展示中文角色名和用户显示名，`actorId` 收进“技术信息”。
- 窄屏使用导航抽屉；图标按钮不小于 44×44px。

### 3.3 问卷工作流框架

新增 `SurveyShell`，统一承载：

- 面包屑：工作台 / 项目 / 文件夹 / 问卷。
- 问卷标题、草稿版本、未保存状态、发布状态。
- 编辑、批量导入、真实预览、发布与版本四个 tab。
- 返回工作区链接 `/workspace?resource={surveyId}`。
- 保留 `question` 查询参数；导入、预览或发布返回编辑时恢复原题目。

版本详情属于“发布与版本”上下文，不再作为孤立页面。

## 4. 工作区设计

### 4.1 页面布局

桌面工作区由三部分组成：

1. 左侧项目导航：只列项目与当前项目内的文件夹树。
2. 主区资源列表：展示当前位置下的文件夹和问卷，支持列表视图。
3. 顶部工具栏：搜索、类型、状态、排序和“新建”菜单，并明确创建目标。

移动端不把整棵树堆在正文上方；项目与位置通过抽屉/面包屑进入，主区仍优先展示当前内容。

### 4.2 资源排序与分页

默认顺序：

1. 文件夹优先于问卷。
2. 同类型按 `updatedAt DESC`。
3. `updatedAt` 相同按中文名称规范化值升序。
4. 最终用 UUID 升序作为唯一稳定 tie-breaker。

排序必须由后端完成，游标编码完整排序键；前端不得只对当前页排序。新建、深链回填和分页数据合并后继续使用同一比较规则。

资源响应增加：

```text
updatedAt: ISO-8601 timestamp
archivedAt: ISO-8601 timestamp | null
```

列表查询增加：

```text
query?: string
kind?: project | folder | survey
archived?: active | archived
sort?: updated_desc | name_asc
```

服务器继续先做授权过滤，再做搜索、状态过滤、排序与游标分页，不能泄露不可见资源名称。

数据库迁移为 `access_resource` 增加：

```text
updated_at timestamptz NOT NULL
archived_at timestamptz NULL
```

迁移时以现有 `created_at` 回填 `updated_at`，不能用迁移执行时间覆盖历史顺序。改名、移动及与资源标题同步的问卷草稿保存必须更新 `updated_at`；普通查看不更新。为常用 active/archived 查询建立包含 `tenant_id`、`parent_id`、归档状态和排序键的索引，并保留 UUID 作为唯一尾键。

默认 `updated_desc` 游标编码 `kindRank + updatedAt + normalizedName + id`，`name_asc` 游标编码 `kindRank + normalizedName + id`。游标是服务端签发的不透明值，客户端不得自行拼接；筛选或排序变化后必须丢弃旧游标重新查询。

### 4.3 资源治理

- 项目、文件夹和问卷支持归档与恢复。
- 非空容器可归档；归档作用于整个子树的可见状态，但不删除数据。
- 默认工作区只显示 active；归档页单独查看。
- 发布中的问卷归档前必须给出影响说明，并由服务端验证操作权限。
- 改名与移动使用现有后端契约接入 UI；问卷改名仍通过保存草稿标题完成。

### 4.4 搜索与最近使用

首轮搜索限定当前租户和当前项目，不做跨租户全文索引。最近使用由前端基于当前会话内真实打开行为维护，不写持久浏览器存储；服务器 `updatedAt` 只表示业务资源变更，不把“查看”伪装成修改。

## 5. 编辑器布局与文案

### 5.1 响应式规则

- `>= 1180px`：大纲、编辑、属性三栏。
- `820–1179px`：大纲 + 主编辑区；属性以右侧检查器抽屉打开。
- `< 820px`：大纲、编辑、属性三个 tab；所有主要触控目标至少 44px。

断点由 CSS 与 React 共用的 `matchMedia` 常量定义，避免 761–980px 出现代码和样式判断不一致。

### 5.2 产品语言

- `L/M/S/T/X` 等题型代码映射为“单选题、多选题、短文本、长文本、说明文字”。
- `zh-Hans` 显示为“简体中文”，底层代码放入技术信息。
- `actorId` 默认显示为“测试管理员”或身份返回的显示名。
- “指纹、sid、编译器、最终授权由服务端判定”等内部术语放入可展开的诊断区域。
- 保存成功展示版本与时间；标题保存后页头、面包屑和工作区缓存同步更新。

## 6. LimeSurvey 入口与 SSL 策略

### 6.1 入口治理

- 业务导航永远不链接到 `/admin`。
- 部署层为 `/admin` 配置独立访问策略，仅允许运维网络或运维身份。
- 原生后台登录页可增加简短中文说明“引擎运维控制台”，但不进行结构性换肤。
- 产品验收入口固定为平台管理端；答卷验收入口为真实运行时 URL。

### 6.2 环境配置

| 环境 | TLS | LimeSurvey 配置 |
|---|---|---|
| 本地测试 | 127.0.0.1 HTTP | `force_ssl=off`、`ssl_disable_alert=true` |
| CI | 容器内部 HTTP | 同本地；不把警告作为产品截图 |
| 测试/生产 | 反向代理 HTTPS | 正确传递代理协议头；验证 HTTPS 后 `force_ssl=on`、`ssl_disable_alert=false` |

启动器必须显式写入环境策略，不能依赖 LimeSurvey 默认值。生产部署健康检查增加 HTTPS 重定向、代理头和安全 Cookie 验证。

## 7. 人工演示与测试数据

### 7.1 租户隔离

- E2E 使用专用测试租户，每次运行继续允许创建时间后缀资源。
- 人工演示使用独立 demo 租户，不复用 E2E 租户。
- 人工服务启动时幂等创建固定资源：`客户体验研究 / 2026 Q4 / 品牌跟踪调查`。
- demo 问卷至少展示基础题型、一个高级题型、品牌主题、审批发布状态和真实答卷链接。

### 7.2 测试数据生命周期

- 自动化资源不进入人工演示租户。
- 在归档 API 完成后，E2E 可在 suite 结束时归档本轮根项目；失败时保留并把根项目 ID 写入脱敏证据。
- 不因清理测试数据引入生产删除接口。

## 8. 真实运行时预览

平台新增短时预览会话：

1. 作者在平台点击“真实预览”。
2. 平台验证编辑权限和当前草稿版本，创建不可提交生产答卷的预览发布作业。
3. 发布网关生成隔离的预览 sid 或受控预览实例，安装 `zh-business` 和所需题型主题。
4. 平台返回短时、一次性或限时预览 URL，在同源受控页面中打开。
5. 预览提交被运行时策略拒绝或写入专用非生产数据域；不计额度、不触发通知、不进入生产投影。
6. 草稿变更使旧预览失效；预览实例按 TTL 回收。

首阶段保留现有“快速草稿预览”，并明确区分：

- 快速预览：即时、基础题型、本地渲染。
- 真实预览：异步、真实 LimeSurvey 运行时、可验证主题与复杂题型。

真实预览涉及新后端/网关契约，单独实施，不与工作区重构绑成一个不可审查的大提交。

## 9. 后续能力入口

完成信息架构后，按以下顺序把已有机制转成页面：

1. 模板库：浏览、复制、版本、审批、下架。
2. 品牌配置：Logo、主色、favicon、多语言页脚及移动/桌面预览。
3. 高级题型第一批：从已有主题中选三类形成配置、预览、发布、作答、导出闭环。
4. 访问策略与考试：时间窗、密码、限次、考试时长和结果可见范围。

每批都必须有真实浏览器演示问卷，不再只以主题目录或服务测试作为可见交付证据。

## 10. 错误、权限与状态

- 搜索和过滤失败保留当前查询条件并提供重试，不清空列表假装没有数据。
- 深链资源无权访问继续返回不可枚举的 404。
- 归档、恢复、移动和改名均由服务端 capabilities 决定；前端隐藏不替代服务端拒绝。
- 真实预览创建失败不影响草稿，旧生产版本继续可用。
- 会话过期继续保留编辑恢复槽；恢复后返回原问卷、tab 和题目。
- 人工 demo seed 失败必须让启动器失败并报告，不允许启动一个空白或被测试污染的“成功”环境。

## 11. 验证策略

### 11.1 单元与组件

- 资源复合排序游标在同名、同时间、跨类型和分页边界下无重复无遗漏。
- 授权过滤先于搜索，不通过关键词推断其他租户资源。
- `SurveyShell` 面包屑、tab、返回路径和 `question` 上下文恢复。
- 三种编辑器布局在 819、820、1179、1180px 边界不溢出。
- 中文题型/语言/角色映射及技术信息折叠。
- 本地/CI/生产 SSL 配置矩阵。

### 11.2 真实浏览器

- 登录后只看到固定 demo 数据，无 E2E 时间后缀资源。
- 从项目进入问卷，完成编辑、导入、快速预览、发布、版本，再返回同一资源节点。
- 768px、1024px、1440px 及移动视口均无横向溢出。
- 工作区移动端触控目标达到 44px。
- 真实预览展示 `zh-business`、租户品牌和至少一种高级题型，且不能形成生产答卷。
- `/admin` 不出现在业务导航，受限环境拒绝非运维访问。

### 11.3 专项验证

- VoiceOver 或 NVDA 完成工作区选择、问卷 tab 切换和题目排序。
- 真实触摸设备验证抽屉、资源列表和排序替代控件。
- 生产样式回归截图与本设计审计截图形成前后对比。

## 12. 分阶段交付与门禁

### 12.1 实施前置条件

- 本设计分支基于 PR #10 的题组/题目排序成果；后续实现不得复制或回退该能力。
- 开始 Phase A/B 前先确认 PR #10 的最终状态。若其尚未合并，新实现需明确依赖并保持提交边界；若已合并，则从更新后的目标分支承接。
- 当前审计发现的旧进度数字和拖拽状态漂移，应在首个实现阶段同步修正现有进度板与追踪矩阵，不另建重复顶层文档。

### Phase A：入口与人工环境

- demo/E2E 租户隔离、固定种子数据、本地 SSL 提醒策略、明确引擎运维入口。
- 门禁：人工登录后首屏无测试垃圾数据；四个本地服务健康；生产配置检查不被本地策略弱化。

### Phase B：工作区与导航

- AppShell、SurveyShell、业务排序、搜索过滤、改名移动归档、上下文恢复。
- 门禁：资源分页无漏重；完整浏览器流程返回原位置；移动工作区可用。

### Phase C：编辑器产品化

- 响应式布局、中文业务文案、状态与版本上下文、专项无障碍。
- 门禁：四个关键宽度无溢出；键盘、读屏和触摸替代路径通过。

### Phase D：真实预览与可见能力

- 真实运行时预览；随后接模板、品牌和高级题型第一批。
- 门禁：真实主题/题型可见，预览数据与生产严格隔离，失败不影响线上版本。

## 13. 方案比较

### 方案 A：平台优先，原生后台仅运维（采用）

升级边界清晰，符合蓝图的“独立商业平台 + 薄插件”架构；投入集中在业务用户真正使用的界面。

### 方案 B：平台与 LimeSurvey 后台双重产品化

短期看起来改动直观，但会维持两套导航、权限和编辑语义，并放大每次上游升级冲突。不采用。

### 方案 C：只清理测试数据和调整样式

能改善第一印象，但不解决随机排序、上下文丢失、双入口和能力不可见等结构问题。不采用。

## 14. 成功标准

- 新用户能在 30 秒内判断应该从哪里创建、编辑、预览和发布问卷。
- 人工测试首屏只有稳定业务数据，不出现自动化时间后缀资源。
- 用户无需进入 LimeSurvey `/admin` 完成任何正常作者流程。
- 工作区与问卷流程在桌面、平板和移动端没有横向溢出或上下文丢失。
- 至少一项模板、品牌或高级题型能力形成“配置 → 真实预览 → 发布 → 作答”的可见闭环。
- 文档分别报告代码存在、自动化通过和用户可见状态，不再用测试数量替代产品完成度。
