# 业务工作台 v1 设计

日期：2026-10-10

状态：待用户书面复核

## 1. 背景与问题

当前管理端已经接入资源管理、基础编辑、批量导入、隔离真实预览、审批发布、正式投放链接、答卷查询和异步导出，
但登录后的 `/workspace` 仍是资源浏览器。用户必须先找到问卷、选中资源、进入问卷，再从二级工作流导航寻找新能力。
全局导航中的“工作台”和“问卷”又指向同一页面，导致已完成能力不可发现，业务待办也无法跨问卷汇总。

本设计只建设第一个独立子项目“业务工作台 v1”。模板与品牌、通讯录与投放、高级题型和运营后台继续按既定波次
分别设计和验收，不在本切片放置空壳入口。

## 2. 目标与非目标

### 2.1 目标

1. 将登录后的默认入口改为真正的业务工作台 `/dashboard`。
2. 将现有资源浏览器保留在 `/workspace`，产品名称改为“项目与问卷”。
3. 通过一个租户级聚合接口展示真实的跨问卷状态，不在浏览器中逐份问卷发起 N+1 请求。
4. 让作者、审核者和数据人员从首页发现需要处理的事项，并直接进入已有的预览、发布、答卷和导出页面。
5. 明确区分无数据、无权限、暂时不可用和加载失败，不再通过隐藏入口制造“功能不存在”的错觉。
6. 在桌面、平板和手机宽度下保持任务、状态和操作可见，不依赖横向裁切的二级标签。

### 2.2 非目标

1. 不在本切片实现模板与品牌、通讯录、批量投放、高级题型或平台运营后台。
2. 不新增统计分析模型，不计算趋势、转化率或业务预测。
3. 不在前端拼装跨问卷状态，不新增轮询型全局事件总线。
4. 不改变现有单问卷编辑、预览、发布、答卷和导出的业务语义。
5. 不把尚未完成的能力以禁用菜单、占位卡片或“即将上线”形式展示。

## 3. 用户与核心任务

| 角色 | 首页核心任务 |
|---|---|
| 作者 | 找到最近问卷；发现待修改、待发布或发布异常；进入编辑、真实预览和发布 |
| 审核者 | 发现当前有权处理的待审批请求；进入固定问卷版本的审批页面 |
| 数据人员 | 发现有答卷的问卷和运行中的导出；进入答卷、导出状态或下载页面 |
| 租户管理员 | 查看本租户业务运行摘要；本切片不提供平台级运营动作 |

工作台只返回调用者当前租户内且服务端授权可见的数据。跨租户对象、不可见问卷和无权处理的审批事项不得通过计数、
名称或错误差异泄露。

## 4. 信息架构

### 4.1 路由

- `/`：重定向到 `/dashboard`。
- `/dashboard`：业务工作台。
- `/workspace`：项目、文件夹和问卷资源管理。
- `/workspace?kind=survey`：保留兼容，仍为资源管理中的问卷筛选视图。
- `/surveys/:surveyId/*`：保持现有单问卷工作流路由不变。
- `/surveys/:surveyId`：新增默认重定向到 `/surveys/:surveyId/edit`。

### 4.2 全局导航

首期只保留两个真实入口：

1. `工作台` → `/dashboard`
2. `项目与问卷` → `/workspace`

模板、数据、通讯录、投放和管理只有在对应纵向波次形成可验收页面后才能加入全局导航。

## 5. 页面结构

页面采用紧凑、可扫描的后台布局，不使用营销式 Hero，也不堆叠装饰性卡片。

### 5.1 页头

- 标题：`工作台`
- 辅助信息：当前租户名称或可公开显示的租户标识；不得显示测试硬编码身份。
- 操作：`刷新`图标按钮，带可访问名称和刷新状态。

### 5.2 状态摘要

用固定高度的四列摘要条展示：

1. 待我审批
2. 发布异常
3. 运行中预览
4. 处理中导出

摘要数字必须与下方当前可见任务使用同一服务端快照。数字为零时仍保留稳定尺寸；无权限不是零，而是隐藏该摘要项并
由响应中的 `visibleSections` 明确说明。

### 5.3 需要处理

按以下优先级合并最多 20 条任务：

1. 发布失败或待核对
2. 待我审批
3. 预览创建失败或关闭失败
4. 导出失败或文件已过期
5. 待发布草稿

每条任务包含任务类型、问卷名称、状态中文文案、更新时间和一个明确主操作。主操作只能指向已有页面，不在工作台内
复制审批、发布或导出状态机。相同问卷的不同任务可以分别出现，任务键必须稳定。

### 5.4 问卷运行情况

展示调用者最近有权访问的最多 20 份问卷：名称、草稿版本、发布状态、已完成答卷数、最近更新时间和快捷操作。
快捷操作按服务端能力返回，仅包括已形成真实页面的 `编辑`、`真实预览`、`发布与版本`、`答卷与导出`。

### 5.5 最近工作

最近工作由服务端保存的用户级最近访问记录提供；v1 不再使用 `WorkspacePage` 组件内存状态。每条记录包含问卷名称、
最后访问的业务页面、访问时间和恢复链接。租户切换、失权或资源归档后，服务端必须过滤不可恢复记录。

最近访问由前端在问卷业务页面稳定加载后显式登记。客户端只能提交问卷 ID 和受控页面枚举；服务端重新校验资源权限，
按页面枚举生成恢复路径并执行单用户有界保留。客户端不得提交或保存任意 URL。缺少持久最近工作时，业务工作台 v1
不能标记完成。

## 6. 后端聚合接口

### 6.1 接口

`GET /v1/dashboard?surveyLimit=20&taskLimit=20`

`POST /v1/dashboard/recent-work`

边界：

- `surveyLimit` 和 `taskLimit` 缺省为 `20`，有效范围 `1..50`。
- 请求只作用于认证会话中的当前租户，不接受租户 ID 参数。
- 响应由一个数据库只读事务生成，摘要与列表使用同一逻辑快照。
- 不返回令牌、公开作答密钥、导出下载地址、引擎管理员信息或内部错误详情。
- 最近工作登记请求为 `{ "surveyId": "...", "page": "edit|import|preview|publish|responses|version", "version": null }`；
  `page=version` 时 `version` 必须为正整数，其他页面必须为 `null`。
- 最近工作登记成功返回 `204`；资源不可见统一返回 `404`，非法页面或版本返回 `422`。
- 每个用户每个租户最多保留 50 条不同恢复目标；同一目标再次访问只更新时间，不增加行数。

### 6.2 响应模型

```json
{
  "generatedAt": "2026-10-10T00:00:00Z",
  "visibleSections": ["approval", "publish", "preview", "export", "survey"],
  "summary": {
    "pendingApprovals": 0,
    "publishExceptions": 0,
    "activePreviews": 0,
    "activeExports": 0
  },
  "tasks": [],
  "surveys": [],
  "recentWork": []
}
```

`tasks[]`：

- `taskKey: string`
- `kind: pending_approval | publish_exception | preview_exception | export_exception | draft_pending_publish`
- `surveyId: string`
- `surveyName: string`
- `status: string`
- `updatedAt: string`
- `targetPath: string`

`surveys[]`：

- `surveyId: string`
- `name: string`
- `draftVersion: number`
- `publishedVersion: number | null`
- `publishState: draft | pending_approval | approved | publishing | published | failed | needs_reconciliation`
- `completedResponses: number | null`
- `updatedAt: string`
- `actions: Array<edit | preview | publish | responses>`

`recentWork[]`：

- `surveyId: string`
- `surveyName: string`
- `page: edit | import | preview | publish | responses | version`
- `targetPath: string`
- `visitedAt: string`

### 6.3 查询与权限策略

- 聚合服务复用现有资源授权、审批授权、答卷摘要授权和导出授权，不解析 JWT 角色猜测权限。
- 摘要计数基于授权过滤后的集合，不能先全租户计数再隐藏明细。
- 问卷列表按 `updatedAt DESC, surveyId ASC` 稳定排序。
- 任务按严重度、`updatedAt DESC`、`taskKey ASC` 稳定排序。
- 单个依赖模块暂时不可用时，接口不得返回伪造的零；返回 `503` 和统一错误代码，由页面提供整体重试。
- 最近工作登记只接受服务端枚举并由服务端生成 `targetPath`；租户、用户、问卷和版本均不得从客户端路径推导。

## 7. 前端数据流与状态

- 新增独立 dashboard API client 和 schema 校验。
- React Query 查询键必须包含租户标识；会话或租户变化时清除旧工作台数据。
- 问卷业务页面稳定加载后，以不阻塞主流程的 mutation 登记最近工作；失败不伪造本地记录，下一次进入工作台时使用
  服务端已有记录。
- 页面首次加载显示与最终布局同尺寸的骨架，避免布局跳动。
- 刷新保留已有数据并显示刷新状态；失败时保留旧数据并明确标注“数据可能已过期”。
- `401`：沿用现有会话清理和重新认证流程。
- `403`：显示无权访问工作台，不降级展示资源名称。
- `422`：仅用于无效查询边界，前端固定参数不应触发。
- `503`：显示依赖暂不可用和重试按钮，不显示全零摘要。

## 8. 响应式与可访问性

- `>= 1180px`：摘要四列；“需要处理”和“问卷运行情况”上下排列，表格保持完整列。
- `820..1179px`：摘要两列两行；任务和问卷使用紧凑列表，不依赖水平滚动完成主操作。
- `< 820px`：摘要单列或两列；每条任务的主操作置于标题后，状态和时间换行。
- 页面标题、区块标题和表格/列表均有语义结构。
- 刷新和异步状态使用 `aria-live`，不抢占焦点。
- 仅图标按钮必须使用 Lucide 图标和可访问名称；熟悉的图标不重复显示冗余文字。
- 所有状态都显示中文文案，不向用户裸露枚举值。
- 键盘顺序与视觉顺序一致，焦点样式清晰，正文和状态颜色满足 WCAG AA 对比度目标。

## 9. 测试与验收

### 9.1 后端

- 聚合结果只包含当前租户和当前用户可见数据。
- 最近工作登记覆盖跨租户、失权资源、非法页面枚举、非法版本、重复目标更新时间和 50 条有界保留。
- 没有审批权限的用户看不到审批计数和审批任务，不能通过数量推断存在性。
- 稳定排序、上限边界和同一逻辑快照有集成测试。
- 发布异常、预览异常、导出异常和待发布草稿分别有正反例。
- 依赖失败返回 `503`，不返回部分零值响应。

### 9.2 前端

- 加载、成功、全空、部分区块不可见、`403`、`503` 和刷新失败均有组件测试。
- 每类任务主操作指向正确的已有路由。
- 各问卷业务页面只在有效资源加载完成后登记受控的最近工作页面枚举。
- `/`、`/dashboard`、`/workspace` 和 `/surveys/:id` 重定向有路由测试。
- 820、1179、1180 像素边界不出现主操作裁切、文字重叠或水平页面滚动。

### 9.3 真实流程

浏览器验收至少覆盖：

1. 登录后进入 `/dashboard`。
2. 首页发现已发布问卷并进入发布页。
3. 从工作台进入答卷与导出页面。
4. 审核者只看到自己有权处理的待审批项。
5. 手机宽度下完成相同导航。

## 10. 文档与状态同步

实现完成且验证通过后：

1. 更新 `platform/docs/productization/capabilities.json` 并重新生成能力映射。
2. 更新 `platform/docs/p2/progress.md`，明确工作台 v1 的完成边界。
3. 在原核查报告旁增加后续修订，不改写历史截图和历史审计结论。
4. 更新 `platform/README.md` 的实际页面、测试数字和本地验证入口。
5. 推送后更新 Obsidian 项目总览，记录分支、提交、测试和未完成项。

## 11. 准出条件

以下条件全部满足才能称“业务工作台 v1 完成”：

- `/dashboard` 可发现且成为默认首页。
- 摘要、任务和问卷运行情况来自真实聚合接口。
- 最近工作由服务端持久记录，进入问卷页再返回工作台后仍可恢复，失权或归档资源不可见。
- 任一快捷操作均进入已有可用页面，不存在占位入口。
- 租户隔离和权限不可推断有自动化证据。
- 桌面、平板、手机浏览器验收通过。
- 能力映射、P2 进度、README 和外部项目记录同步。

该切片完成不代表模板、品牌、通讯录、投放、高级题型、运营后台或整体产品已经验收。
