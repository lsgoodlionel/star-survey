## 1. 背景与目标

蓝图把管理及业务页面定为 React 与 TypeScript，但当前仓库只有 Spring Boot REST API、发布网关和 LimeSurvey 作答端，没有管理端前端。实证修订把“管理端前端”列为当前投入产出比最高的缺口：大量需求已有后端机制，却因为缺少作者可见界面、移动适配和浏览器验收而只能维持部分完成。

首期建设一个可真实使用的问卷作者工作台，完成以下纵向流程：

1. 登录并确认当前租户、用户和角色。
2. 浏览项目、文件夹和问卷资源。
3. 创建空白问卷，编辑基础结构，或通过批量文本预览后导入题目。
4. 预览当前草稿并保存，遇到并发修改时不覆盖他人版本。
5. 提交发布审批、查看审批历史并发布获批版本。
6. 正确展示发布成功、失败和待核对状态，查看已发布版本。

成功标准不是“页面存在”，而是一条真实浏览器流程能够通过现有平台、发布网关和测试引擎完成创建到发布，并留下自动化验收证据。

## 2. 设计原则

- 平台 API 继续承担租户、权限、校验和状态机决策；前端不复制服务端授权规则。
- 前端只调用平台 `/v1` API，不接触发布网关或 LimeSurvey 管理 API。
- 采用工作型管理界面，优先信息密度、连续操作和状态可追踪，不做营销首页。
- 编辑器只修改明确拥有的定义字段；未知字段和暂不支持的复杂题型必须原样保留。
- 服务端状态与未保存编辑状态分离，后台刷新不能覆盖作者正在编辑的内容。
- 中文是默认界面语言；后端英文状态码与错误在界面层翻译为明确中文。
- 真实流程验收优先于纯 mock 演示；mock 只用于快速、确定性的组件和异常分支测试。

## 4. 总体架构

在 `platform/apps/admin-web/` 新建独立 SPA：

```text
浏览器
  |
  | 同源 /v1 + Bearer JWT
  v
管理端 Web 容器 ----> 平台 Spring Boot ----> PostgreSQL
                              |
                              v
                         发布网关 ----> LimeSurvey
```

本地开发由 Vite 代理 `/v1` 到平台服务。Docker 和交付环境由管理端 Web 容器提供静态文件，并把 `/v1` 转发到平台服务。这样无需增加 CORS 白名单，也不会向浏览器暴露内部网关地址。

前端使用：

- React 与 TypeScript：页面和领域状态。
- Vite：开发与生产构建。
- React Router：URL、选中资源和编辑位置。
- TanStack Query：服务端查询、缓存和失效。
- React Hook Form：字段表单与可访问错误关联。
- Zod：API 响应的运行时校验。
- Vitest、Testing Library、MSW：单元、组件和页面流程测试。
- Playwright：真实浏览器纵向验收。

首期不引入全局状态框架。认证会话由顶层 provider 管理；正在编辑的问卷由编辑器 feature 管理；服务端数据由 TanStack Query 管理。

## 5. 信息架构

### 5.1 应用框架

- 左侧导航：项目、文件夹和问卷资源树。
- 顶栏：当前租户、用户、角色、发布状态入口和账户菜单。
- 主区：工作区、编辑器、导入、预览、发布和版本页面。
- 桌面编辑器使用稳定三栏：题组/题目大纲、主要编辑区、当前对象属性。
- 窄屏设备改为大纲、编辑、属性三个标签页，避免内容重叠和不可操作的窄列。

### 5.2 路由

| 路由 | 职责 |
|---|---|
| `/auth/callback` | 消费单次登录交接并建立内存会话 |
| `/workspace` | 资源浏览与项目、文件夹、问卷创建 |
| `/surveys/:surveyId/edit` | 草稿结构化编辑 |
| `/surveys/:surveyId/import` | 文本导入预览与确认 |
| `/surveys/:surveyId/preview` | 草稿桌面/移动预览 |
| `/surveys/:surveyId/publish` | 审批、发布和状态追踪 |
| `/surveys/:surveyId/versions/:version` | 已发布版本只读详情 |

选中的资源、题组和题目写入 URL 或路由状态。页面切换后恢复工作位置，不依赖不可追踪的全局变量。

## 7. 问卷定义编辑模型

后端草稿仍以完整 JSON 为真源。前端建立 `SurveyDefinition` 适配层，但不创造另一套持久化格式。

适配层负责：

- 解析当前定义并保留未知顶层字段、题组字段、题目字段和扩展字段。
- 用稳定 UUID 标识题组与题目；排序只调整数组位置，不重建 UUID。
- 编辑标题、说明、题组、题目文本、代码、类型、必答和选项等首期字段。
- 对复杂题型显示只读摘要；保存时把未拥有字段原样合并回定义。
- 新建对象使用确定的默认值和新 UUID；题目代码在当前问卷内唯一。
- 保存前检查缺失标题、空题组、重复代码、空选项和当前控件可判定的结构问题。

服务端仍执行完整校验。前端校验只改善交互，不作为安全或发布依据。

## 8. 状态与数据流

### 8.1 启动

1. 应用从内存会话取得 JWT。
2. 请求 `GET /v1/me`，确认租户、用户和角色。
3. 失败或令牌过期时清除内存会话并回到登录入口。
4. 客户端角色只控制动作展示；服务端 `403` 仍是最终判定。

### 8.2 编辑与保存

1. 同时读取问卷概览和草稿。
2. 编辑器记录服务端 `draftVersion`、基准定义和本地工作定义。
3. 保存时提交完整定义和 `expectedVersion`。
4. 成功后用响应中的新版本替换基准，并清除脏状态。
5. 页面切换保留本地工作定义；离开问卷或关闭页面时对未保存内容给出明确确认。

若出现乐观锁冲突：

- 不自动重试，不覆盖服务端新版本。
- 保留本地工作定义。
- 告知已有其他修改，并提供重新载入与导出本地草稿两个动作。
- 首期不承诺自动字段合并。

### 8.3 导入

1. 用户粘贴文本并调用预览 API。
2. 页面按题目和坏行展示结果，默认勾选合法题目。
3. 用户确认后带当前 `expectedVersion`、原文、选中序号和目标题组提交。
4. 导入成功后以服务端返回的新草稿替换编辑状态。
5. 导入期间发生冲突时沿用编辑保存的冲突规则。

### 8.4 审批与发布

审批动作严格映射现有状态机：`pending`、`approved`、`rejected`、`withdrawn`、`voided`、`published`。保存新草稿可能使已批准申请变为 `voided`，界面不能继续显示为可发布。

发布响应处理：

- `200`：发布成功，刷新问卷、审批和版本。
- `202`：发布中或待核对，展示持续状态并轮询问卷概览。
- `422`：定义被拒，定位并展示可用的失败信息。
- `502`：发布失败，展示安全的失败阶段与处理建议。
- `401/403/404/409`：走统一错误规则。

若 `lastPublish.manualReviewAt` 非空或 `orphanEngineSid` 非空，显示不可忽略的人工处理告警；前端不提供未经后端支持的“强制重发”。

## 9. 浏览器认证交接

现有组织登录回调直接返回含 JWT 的 JSON，浏览器应用无法安全完成导航。首期增加可选的 SPA 交接模式，不改变 JWT 验签、租户声明或组织平台兑换逻辑。

流程：

1. 前端从固定、已配置的登录入口发起组织免登。
2. 提供方回调完成身份核验后，平台生成随机、短时、单次使用的 `handoff`；此时不创建平台会话，也不签发 JWT。
3. `handoff` 与当前浏览器的 HttpOnly Cookie 摘要绑定；数据库只保存两个随机值的摘要、完成签发所需的最小身份引用和到期时间，不保存 JWT。
4. 平台重定向到固定配置的管理端 `/auth/callback?tenant=...&handoff=...`；租户标识只用于把匿名交换限定到对应 RLS 作用域，不参与身份提升。
5. 前端调用带同一租户路径的匿名交换端点；端点同时核对租户作用域、`handoff`、浏览器 Cookie、到期时间和未使用状态。
6. 原子消费成功后才创建现有可撤销平台会话并签发 JWT，然后立即清除交接 Cookie。

约束：

- `handoff` 最长存活 60 秒，只可消费一次。
- 重定向目标来自服务端固定配置，不接受任意调用方 URL。
- JWT 不进入查询参数、片段、日志或持久化浏览器存储。
- JWT 只在当前页面内存保存；刷新或关闭页面需要重新登录。
- 本地测试令牌入口仅由开发构建开关启用，生产构建不包含该交互入口。

首期不增加 refresh token。现有 10 分钟令牌到期后重新登录；后续若体验证明确需长会话，再单独设计可撤销刷新会话。

## 10. API 适配与错误模型

API 模块按 `me`、`resources`、`surveys`、`imports`、`approvals` 划分。每个函数定义请求、响应和运行时 schema，不在 React 组件中直接使用 `fetch`。

统一错误类型至少包含：

- `unauthenticated`
- `forbidden`
- `not_found`
- `conflict`
- `validation`
- `pending`
- `unavailable`
- `unexpected`

界面映射：

| HTTP/状态 | 用户说明 |
|---|---|
| 401 | 登录已失效，请重新登录 |
| 403 | 无权执行当前操作 |
| 404 | 资源不存在或不可访问 |
| 409 | 草稿已被其他人修改，本地内容未被覆盖 |
| 422 | 定义或导入内容未通过校验 |
| 202 | 发布结果正在核对 |
| 5xx/网络错误 | 服务暂时不可用，请稍后重试 |

未知错误不展示堆栈、令牌、网关口令或原始敏感响应。若后端提供安全追踪编号，界面保留该编号用于排障。

## 11. 视觉与可访问性

- 默认中文，状态文本不显示无说明的英文枚举值。
- 使用紧凑、清晰的工作台层级；卡片只用于重复实体和对话框，不把整个页面堆成卡片。
- 图标按钮使用统一图标库并提供 tooltip 与可访问名称。
- 颜色不是状态的唯一表达，状态同时提供文字和图标。
- 所有字段有可关联标签；错误说明与字段通过 ARIA 关系连接。
- 键盘可以完成资源选择、表单编辑、保存、导入确认和审批操作。
- 焦点轮廓清晰；对话框打开、关闭和校验失败后的焦点位置可预测。
- 固定工具栏、大纲和编辑区使用明确的响应式尺寸，动态状态不能推动整体布局跳动。

## 16. 主要风险与处理

| 风险 | 处理 |
|---|---|
| 定义格式未有单一 JSON Schema | 以当前网关契约、Java DTO 与真实 fixture 建运行时 schema；不猜测未支持字段 |
| 基础编辑器误删复杂题型扩展 | 未拥有字段原样保留，并用往返测试钉死 |
| 10 分钟 JWT 导致长时间编辑中断 | 未保存内容留在编辑状态；401 后重新登录，恢复页面上下文；刷新会话另立设计 |
| 资源树列表缺少问卷状态汇总 | 首期在选中问卷后加载概览；若真实使用出现明显 N+1，再增加专用批量查询 API |
| 本地预览与真实引擎存在差异 | 明示“草稿预览”；真实发布验收继续走引擎，不把本地渲染当运行时一致性证明 |
| Playwright 栈较重 | 组件流程保持快速；真实纵向门禁只保留一条高价值主路径和必要异常锚点 |
| 前端依赖供应链扩大 | 锁定版本、提交锁文件、CI 审计，避免引入功能重叠的大型依赖 |

## 17. 后续演进

首期稳定后，按需求断言优先扩展：

1. 逻辑、计分、访问策略和品牌的可视配置。
2. 复杂题型与资产编辑。
3. 真实引擎预览和移动端交互取证。
4. 多人协作、自动保存和字段级冲突处理。
5. 统计、投放、通讯录和考试工作台。

每项扩展单独对照需求矩阵设计和验收，不用“已有管理端”替代具体功能完成证明。
