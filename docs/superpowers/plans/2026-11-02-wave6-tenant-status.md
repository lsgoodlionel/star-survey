# Wave 6 租户状态管理

此切片以 PR #44 的人员会话、独立授权和服务端 capability 为前置依赖；合并前 PR 以其分支为 base，合并后改回 main 并核对最终 head。详情页使用已有状态 API，变更前显式确认，关闭显示不可恢复；服务端状态机与审计仍是权威，冲突或未知结果先重新读取，不自动重试写入。失权时隐藏租户详情，不能根据旧角色或缓存继续操作。所有测试使用隔离租户，不改真实租户。

隔离 HTTP 测试要求已验签人员令牌、有效 sid 与独立 grant，覆盖状态修改、非法迁移、审计、旧无 sid 角色拒绝及撤权后写入拒绝。组件测试覆盖确认、终态、服务端 403 和并发冲突。双库浏览器门禁的独立后置阶段开启人员 guard，以隔离会话和 grant 完成真实浏览器状态变更，核对审计，撤权后验证 API 与页面拒绝并验证旧令牌不再可用；原有旧运营令牌旅程不能充当人员路径证据。该新阶段的最终双库 CI 结果仍须按精确 head 核对。

生产准出还需同一候选在四个 Ubuntu/架构节点证明升级，现有 bootstrap 模式跳过升级不满足路线图。先准备两个连续且均经审查、支持同一 auth-security-floor 的隔离候选，验证第一候选安装、业务数据与备份，再由第二候选升级、核对数据、恢复及重新授权，核对两候选摘要、签名和证明；旧安装到新安全边界的迁移另测失败关闭。实际候选 tag、镜像和 Release 只在父任务取得明确发布授权后执行，不能用 bootstrap 结果代替升级证据。

后续运维修正：升级失败恢复中 Docker stop 调用可能失败，不能保证服务已停止；应保留 recovery_required 并明确报告尝试停止及未知状态，再提供可验证的人工处置与失败测试。
