# Wave 6 平台管理员实施计划

依据 `2026-11-02-platform-administrator-authorization-design.md`，按独立切片推进：

1. 明确人员与现有机器探针的信任边界、数据库授权和 bootstrap，建立失败测试及隔离授权存储与审计；不可授予真实身份。
2. 将服务端能力和人类运营 API 接到逐请求授权；迁移前先完成探针独立机器身份和兼容性测试，保留安装与发布链。
3. 补前端入口、身份切换和失权恢复；针对跨租户、撤权、并发与故障执行隔离测试和 GitHub CI。
4. 父任务独立安全审查数据库迁移、授权、机器兼容与生产准入；真实 IdP、realm、首个管理员和生产配置均须明确授权和验证。

2026-11-02 原型边界：运行数据库账号仅可检查当前授权，不能调用 bootstrap 或授权变更；不提供 HTTP 写入口。直接把应用传入的 actor 参数交给安全定义函数，数据库无法证明其与已验证会话一致，会产生伪造审计及越权风险。人员授权写入机制、目标身份有效性验证、现有机器探针隔离和端到端接入必须先完成设计与独立安全审查。本原型未连接现有运营路由，不能作为已完成角色或生产登录方案。

2026-11-02 补充：资源服务器测试使用真实签名与会话校验覆盖过期、撤销、主体/租户不匹配、错误 issuer 和无 sid。原型的可用身份检查纳入已撤销绑定和暂停租户，bootstrap 记录数据库会话用户及原因；共享数据库用户不能单独证明具体自然人。身份离职/租户停用与授权变更尚未建立共同串行化和受控恢复；离职撤权必须立即生效，不能为了维持管理员数量而保留已失效人员的权限。该并发和零可用管理员恢复场景、可信人员写入主体与机器凭据隔离仍属阻断，运行时写入口保持关闭。

2026-11-02 隔离增量：身份绑定撤销、成员/连接状态变化及租户状态变化与授权写入使用同一数据库事务锁；不可用身份的现存 grant 被持久标为失效并写系统审计，身份恢复后必须由另一位有效管理员显式重新授权。安全撤销不因最后管理员失效而阻拦；零可用管理员时，仅数据库属主可按明确目标和原因执行独立恢复函数。该函数默认无运行账号执行权，也不构成生产 bootstrap/恢复操作许可。恢复及自动失效审计目前只能记录数据库会话用户，不能据此认定具体自然人；人类操作者归因、恢复执行通道、身份变更与授权并发的完整压力/故障验证仍须审查。真实人员写接口及机器 guard 迁移未接入。

隔离操作者解析器只从 Spring Security 的验签会话上下文构造人员身份，并重新查询平台 grant；测试用 HTTP 端点验证伪造请求体中的 actor 无效、撤权后拒绝。它尚未授予数据库写权限，也不替代写入事务内的授权复查。写入通道仍需单独设计可验证的应用到数据库信任边界，禁止把请求体 actor 直接传给属主函数或让运行进程使用数据库属主。

隔离 capability 解析器每次从已验证人员会话和实时 grant 得到 `managePlatform`，签名 HTTP 测试覆盖有效 grant、成员撤权和无 sid 的旧机器角色；此解析器仅由测试端点调用，尚未接入导航或运营路由，不能代替后续接口判权。

锁序增量：身份状态写语句的 BEFORE STATEMENT 钩子先取得与授权写入相同的事务级锁，再取得受影响行锁；锁阻塞测试先持授权锁，确认并发连接更新等待时尚未锁住连接行，并覆盖多成员批量失效和恢复。该全局锁会串行化这些身份写入，需在启用前评估吞吐与跨模块事务锁序；若调用方在写语句前已持有其他行锁，仍可能发生死锁。数据库死锁（40P01）或序列化失败（40001）必须回滚整个事务；在没有外部副作用且已确认事务未提交时才可有限次重试，审计与授权变化不得部分提交。尚未在应用入口实施通用自动重试，也未对外部供应商调用做重试。

事务内复查原型：仅数据库属主可调用 `platform_admin_change_session`；事务先取得授权锁，再锁定并核对 sid、租户、主体、未撤销和实时到期，随后复查操作者 grant、目标可用性并与审计一起提交。运行账号无函数执行权；数据库无法仅凭调用参数证明 actor/sid 来自签名令牌，因此这还不是应用写入通道，也不能使用属主连接开放它。

应用到数据库的可信写入边界需要选择：

- 方案 A：数据库验证短时、非对称签名的授权断言，仅持公钥；断言明确 issuer、audience、actor、sid、目标、动作、过期时间和一次性标识，数据库在同事务验签、防重放、复查会话与 grant 并写审计。数据库可独立约束参数，即使应用 SQL 调用参数被篡改也不能伪造断言；需要可信 JOSE 验证实现、公钥轮换、防止数据库日志记录令牌，并把现有组织会话从共享 HMAC 迁向 ADR 0010/0014 的非对称身份。不能自行发放真实签名凭据或部署扩展。
- 方案 B：独立授权写服务使用专用、仅可调用窄函数的数据库角色，自己验证用户会话及 grant，再在数据库事务中复查并审计；主应用账号不能调用写函数。部署与密钥轮换较简单地隔离在服务边界，数据库信任该写服务传入的 actor，若写服务被攻陷可伪造 actor；需要新增服务身份、数据库角色/凭据和部署配置，且这些真实变更尚未获批。无论选哪项，服务端不能使用数据库属主连接处理请求，且 bootstrap/recovery 必须可归因到实际部署操作者。

现有生产 setup-probe 使用共享人员 HMAC 签发无 sid 的 platform_operator；它实际调用六类端点：创建租户、发布套餐、租户开通、变更租户状态、注册引擎实例、领取引擎事件密钥。独立机器凭据必须有自己的验签信任、audience、短期有效期及逐方法/路径权限，且把动态租户/实例限定到当前探针创建的资源；事件密钥读取尤其不能对普通机器开放。先做隔离 install/probe 回归、切换与回滚，再移除旧 guard，不能单凭 subject 区分机器。
